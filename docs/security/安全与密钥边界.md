# 安全与密钥边界

## 1. 禁止提交

1. `local.properties`、`keystore.properties`、`.codex/local-context.properties`。
2. `.jks`、`.keystore`、私钥、密码、token、证书和生产配置。
3. 本机绝对路径、车机网络地址、设备日志、截图、录屏、缓存和构建产物。
4. 包含播放历史、设备标识或第三方服务响应中敏感字段的 fixture。

## 2. Android 权限边界

1. 通知使用权只用于取得公开 MediaSession，不读取普通通知正文。
2. 悬浮窗只用于用户主动开启的歌词表面。
3. 蓝牙附近设备权限只用于显示已连接音频设备名称。
4. 网络只用于用户当前歌曲的歌词 / 备用封面，以及 Device Commerce 的试用、公开活动、报价、购买轮询、许可证刷新和同设备恢复；商业接口不上传播放内容。
5. 开机广播只恢复用户已明确保持开启的歌词服务。
6. “歌词窗口避让”无障碍服务只接收 `com.mengbo.launcher3` 的窗口状态、窗口列表和子树结构事件，且只读取交互窗口边界与根节点所属包；不读取节点文字、不执行节点动作、不点击、不模拟手势。它不写车辆状态，也不连接 CAN 或车厂私有接口；不可用时壁纸态保守回顶栏。
7. 新增权限必须同步产品基线、Manifest、隐私说明和运行级验证。
8. 普通 APK 不能自行开启通知使用权、悬浮窗特殊访问或无障碍服务；目标车机通过外部受控调试设置出的状态只属于该设备，不能随 APK 分发。应用设置页不提供无法在当前固件中完成触摸操作的系统授权入口，也不使用私有组件绕过系统安全策略。
9. 零点击可用仅适用于车厂平台签名或特权系统组件发行：系统镜像或特权安装器必须同时提供对应白名单和授权配置。没有车厂签名、系统镜像或等效受控部署权限时，不得把该能力写成普通 APK 的承诺。
10. 表面占用租约 Service 为跨应用发现而显式导出，但只接受固定 Action、只返回无业务方法的 Binder，绑定方只能请求歌词保守退回顶栏；不得借此暴露数据、设置写入、窗口控制或其它应用权限。

## 3. 商业与设备密钥边界

1. 设备身份只使用 AndroidKeyStore 内不可导出的 P-256 EC 私钥；初始别名为 `03lyrics_device_key_v1`，恢复换钥使用受加密状态约束的待确认别名。对外只允许 SPKI、公钥 SHA-256、签名证书 SHA-256、设备指纹和签名结果。Android Key Attestation 只作能力探测，不支持时不阻断普通车机。
2. 设备指纹固定为 `SHA-256(ANDROID_ID + NUL + packageName + NUL + 安装包签名 SHA-256 十六进制文本)`；原始 `ANDROID_ID`、签名证书和拼接原文不得写入日志、Telemetry、URL、fixture 或普通存储。
3. challenge 只签 Base64 解码后的 32 字节；购买轮询只签合同规定的四行 UTF-8 原文。签名、poll token、device token、完整设备指纹和 nonce 不进入日志、URL、Telemetry 或普通偏好。
4. 许可证必须先验证原始 payload 的 P-256 / SHA-256 签名，再解析 claims，并核对 envelope / payload / 配置 `keyId`、版本、产品、当前设备公钥摘要、密钥版本、签发时间、到期时间、离线宽限和试用截止。Release 正式公钥与 `keyId` 未配置时 fail closed，不得使用 Debug 签名或本地布尔值替代。
5. 许可证、device token、poll token、未完成支付会话、首次打开时钟、许可证可信时间、自动续签失败后的下一次允许时间、设备密钥版本、活动别名和待确认恢复别名使用独立 AndroidKeyStore AES-GCM 密钥 `03lyrics_commercial_storage_key_v1` 加密，每类记录以记录名作为 AAD 并写入 `noBackupFilesDir`；应用整体关闭 Android 备份，商业记录禁止进入普通 SharedPreferences、日志、URL 或 Telemetry。
6. 同设备恢复不生成或保存 `recoveryCredential`。旧钥存在时对 recover challenge 附签；旧钥丢失时只允许同指纹恢复。待确认新钥必须在请求前持久化，网络或进程中断后复用，避免云端已换钥而客户端丢失新私钥。
7. Debug fixture 的金额、活动码、订单、二维码域名和许可证签名键只存在于 `app/src/debug` 或测试；Debug 签名键由 Debug 进程在 AndroidKeyStore 内生成，不把静态测试私钥打包进 APK。fixture 仍走正式 JSON 解析、设备签名和许可证验签主链。
8. staging 与 production 的 API 基址、许可证公钥、`keyId` 和预期 APK signer SHA-256 只从构建配置进入集中装配。默认 Debug 为本地 fixture；非 fixture 配置不完整、摘要格式错误或实际 signer 不匹配时不会创建网络网关。正式私钥、pepper、支付密钥和服务端 token 永不进入客户端仓库或构建参数。
9. staging APK 使用仓库外长期保存的独立签名身份，不复用开发机自动 Debug 证书；production 必须另建独立身份，不复用 staging。keystore、口令和私钥不得进入仓库、文档、日志或聊天，对 Cloud 只交付实际 APK 的签名证书 SHA-256。
10. 歌词运行资源只接受统一 `CommercialAccessGate` 的 `Allowed` 决定，不接受界面显示状态、设置页开关或普通偏好作为权益真值。运行服务只缓存门禁已经返回且尚未到最终有效时间的单个运行许可；到点重新读取同一门禁，撤销、过期、存储失败或其它 denied 结果先清除运行许可并释放 MediaSession、WebView 与 Overlay。网络不可用时仍只在签名许可证声明的有效期或 Pro 离线宽限内运行，不增加高频权益轮询。
11. 自动权益复核只在本地无有效许可证或签名 `expiresAt` 已到时发起；连续服务只通过现有主线程 Handler 安排一个续签点回调，同进程并发合并为一次。瞬时失败在仍有本地有效权益时写入 `24h` 自动重试冷却并只重排一个新回调，但不得修改 `expiresAt`、`offlineGraceUntil` 或运行门禁；用户主动重试绕过冷却。Debug fixture 模拟试用一次签发覆盖原七天截止、Pro 第 `7` 天进入续签且签发后第 `90` 天为最终离线终点，production 时间仍只接受服务端签名声明。
12. Release 固定启用 R8 优化、混淆和资源收缩，并显式关闭调试与 JNI 调试；mapping 只在内部保留。当前 APK signer 在非 fixture 运行时只读取一次并与构建注入摘要比较，不做 APK 全量哈希、常驻反调试、Root / Hook 轮询或商业加固壳。
13. Android instrumentation 以目标应用身份运行，不能把测试 APK 的独立包名误当成数据隔离。商业 instrumentation 不属于普通开发收尾，默认只在一次性模拟器或通过 `COMMERCIAL_TEST_ADB_SERIAL` 独立配置的专用测试设备运行；必须使用独立文件前缀、独立 AES / EC / fixture 签名密钥和非单例运行时，测试前后比对正式加密记录并删除测试状态。用户日常车机默认禁止，只有用户当次明确授权且脚本收到 `--user-approved-persistent-vehicle` 时才可例外；不得以测试需要为由清除正式数据或自动重启设备。

## 4. 第三方与来源边界

1. 歌曲名、歌手、专辑和时长会按需发送给 LRCLIB、QQ 音乐和网易云；请求不经过本项目自建服务器。
2. 外部歌词和封面归相应服务及权利人所有，缓存只服务本机显示。
3. 上游仓库历史被保留用于来源追溯，但仓库当前未发现许可证文件；公开发布和重新授权前必须人工确认。

## 5. 人工门禁

普通施工完成后的 debug APK 保留数据覆盖安装和应用范围最简 smoke 已获项目级持续授权。以下动作仍必须先取得用户当次明确指令：

1. 创建或替换签名、修改包名或升级身份。
2. 安装 release、降级安装、卸载应用、清除数据或重启车机。
3. 创建 GitHub Release、上传 APK、公开发布或更改仓库可见性。
4. 新增高风险权限、车辆私有接口或收集用户数据。
5. 安装 Release、注入正式商业公钥 / `keyId` / production 基址、接入 staging / production、真实支付、退款撤权和真实恢复接口。
6. 在用户日常车机安装 androidTest APK、运行商业 instrumentation、临时暂停无障碍或强制结束应用；授权必须针对当次测试，不能由历史授权或“高风险改动”自动推导。
