# iCAR 车机 UI 设计规范

## 1. 适用范围与取证对象

1. 本规范定义 `03lyrics` 在目标 iCAR 03 上复用原车视觉语言时的证据方法、全局基础和已验证页面模式；它不是只服务设置页的单页说明，也不是对全部原车页面的无证据概括。
2. 当前已验证两类原车取证对象：
   1. “设置 → 显示”：`com.chery.carsettings` `1.0.0.743`，页面模式 A 为左侧导航 + 右侧内容双栏。
   2. “应用中心 / 智能场景”：`com.android.launcherMB` `56.24.4.9`（versionCode `9`），系统 APK 位于 `MB_NegativeScreen`；页面模式 B 为顶部标签 + 可滚动内容，其中应用中心使用五列图标网格，智能场景使用三列任务卡片。
3. 原车 APK、位图、图标、插画和私有 MBUI 控件只用于本地取证，不进入仓库；仓库只沉淀可追溯的数值、语义和实现边界。
4. 本规范直接约束 `03lyrics` 原生设置页；歌词悬浮层仅可复用经过跨页面验证的全局基础，不套用设置双栏或应用网格结构。`03桌面` 是独立产品，不属于本仓库。
5. 最终使用者是在车内快速读取状态或完成设置的车主。界面只呈现任务、当前状态和可执行动作，不解释系统键、资源 token 或调试信息。

## 2. 证据等级

| 等级 | 来源 | 可用于确定 | 禁止推导 |
|---|---|---|---|
| A：资源真值 | 原车 APK 的资源表、编译 XML、ARGB token 和尺寸 token | 原始颜色、alpha、物理 px、圆角、控件绑定 | 未在布局或主题中形成引用链的 token 不能直接套用 |
| B：运行态真值 | `dumpsys`、系统配置、包信息和已验证公开设置键 | 窗口边界、密度、深浅模式、当前主题键 | 不能据此猜测私有控件内部实现 |
| C：截图测量 | 同屏深浅截图及像素边界 | 最终观感、位置、可见尺寸、底层透出程度 | 半透明层合成后的像素不能反推为原始颜色或 alpha |
| D：项目适配 | 本项目的内容结构、可维护性和触控需求 | 项目最终采用的尺寸、文案、交互和降级策略 | 不能写成“原车就是这样” |

任何新数值进入本规范前必须标注来源等级。A/B 与 C 冲突时，先检查密度换算、嵌套 padding、九宫格缩放和底层画面，不用截图取色覆盖资源真值。

## 3. 坐标、窗口与单位

1. 原车设置页与应用中心的标准浮窗运行态边界均为 `(660, 90) .. (1890, 900)`，物理尺寸 `1230 x 810 px`。
2. 该窗口的 Android 配置空间为 `1395 x 919 dp`，`densityDpi = 141`，字体缩放为 `1.0`。
3. 原车 MBUI 大量使用物理 `px` 资源；本项目使用标准 Android `dp/sp`。唯一换算公式为：

```text
项目 dp 或 sp = 原车物理 px x 160 / 141
目标车机物理 px = 项目 dp 或 sp x 141 / 160
```

4. 禁止把原车 `84px` 直接写成 `84dp`，也禁止把截图像素直接当成 `dp`。常用换算如下：

| 原车物理值 | 精确换算 | 项目 token |
|---:|---:|---:|
| `6px` | `6.81dp` | `7dp` |
| `12px` | `13.62dp` | `14dp` |
| `18px` | `20.43dp` | `20dp` |
| `24px` | `27.23dp` | `27dp` |
| `26px` | `29.50dp` | `29.5dp` |
| `35px` | `39.72dp` | `40dp` |
| `42px` | `47.66dp` | `48dp` |
| `84px` | `95.32dp` | `95dp` |
| `126px` | `142.98dp` | `143dp` |

5. 上述窗口边界同时在设置页和应用中心运行态成立，可作为当前目标设备的“标准右侧浮窗”模型；窗口里的布局规格仍按页面分别取证，不能因为窗口相同而共享背景、padding 或内容结构。
6. 坐标分三层记录：整屏物理坐标、窗口局部物理坐标、项目 `dp/sp`。文档中的应用中心布局值均为窗口局部物理 `px`，运行态整屏坐标需加窗口原点 `(660, 90)`。

### 3.1 标准浮窗生命周期动效

1. 标准右侧浮窗出现时，整个 `1230 x 810px` 窗口从最终位置下方完整上移到 `(660, 90) .. (1890, 900)`；关闭时从最终位置完整下移退出。底层页面保持静止，不能与前景窗口反向移动。
2. 位移只沿 Y 轴：进入为 `fromYDelta = 100%p -> 0`、时长 `150ms`；退出为 `0 -> 100%p`、时长 `300ms`。不叠加淡入淡出、缩放、横向位移或回弹，也不声明自定义插值器。
3. 方向和时长由原车 `com.chery.carsettings` 中 `bottom_in` / `bottom_out` 的编译资源提供 A 级参数证据；主页面主题没有直接绑定这两份动画，因此本项目将其作为用户已明确确认的 D 级标准窗口行为采用，不反向宣称原车设置主页面的全部系统入口都由这两个文件驱动。
4. 动效必须绑定在 Activity 的窗口动画样式，统一覆盖窗口显示/隐藏、Activity 打开/关闭、任务前台/后台和壁纸前后台转换；页面内容层不得再启动第二套平移动画，也不能只在某个关闭按钮回调中补动画。
5. 本规则只适用于采用标准右侧浮窗模型的完整页面。歌词悬浮层、系统 Toast、局部确认弹窗、分段选中和列表滚动各自遵循所属组件规则，不能套用整窗进出动效。
6. 验收必须使用车机录屏逐帧确认首尾方向，并在静止帧复核最终窗口仍为 `1230 x 810px`；进入结束和退出开始都不得发生尺寸跳变、背景分层错位或触控区域滞留。

### 3.2 标准浮窗占用与跨应用契约

1. B 级运行态证据：目标车机的 `Settings.Secure` 键 `com.mengbo.launcher3.settings.secure.window_mode` 在无窗口桌面为 `0`，左侧 ADAS / 充电卡片单独展开时为 `1`，原车设置、行车记录仪、应用中心和本项目设置页成为前台标准浮窗时为 `2`；左侧卡片和标准浮窗同时存在时为 `3`。
2. 窗口值按区域语义处理，不按“非零即冲突”处理：`0/1` 不占用桌面歌词区域，允许壁纸歌词；`2/3` 含标准右侧浮窗，歌词退回顶栏；其它值或读取失败按未知占用保守退回顶栏。正式功能只注册 ContentObserver 并读取该键，禁止写回、轮询或连接厂商私有窗口服务。
3. 任意标准浮窗出现时，桌面歌词切换为顶栏歌词；窗口存在只改变歌词表面，不改变歌词可见性。只要顶栏安全几何有效，歌词层必须保持可见；窗口关闭后按启动器当前状态和用户“壁纸歌词”偏好重新计算表面。
4. 其它应用的自定义桌面面板若会进入歌词桌面区域，使用版本 `1` 的通用占用租约：发现 `com.tcrrry.icar.surface.action.ACQUIRE_OCCUPANCY_LEASE` 后绑定对应 exported Service，绑定存续期间歌词强制顶栏，解绑后重新按本节窗口语义计算。接收端只接受该 Action 并返回无业务方法的 Binder，不按调用方包名分支。
5. 采用本规范完整标准浮窗模型的第三方 Activity，通过清单元数据 `com.tcrrry.icar.window.STANDARD_FLOATING_WINDOW = true` 主动声明身份。该声明是启动方可读取的能力契约，不依赖包名、签名或开发者身份。
6. 多个标准浮窗的互斥编排归实际启动方所有：启动方应在启动已声明页面前先让当前标准浮窗退回桌面，再启动目标页面。本仓库不写其它产品逻辑，也不通过关闭其它应用、前台扫描、无障碍或私有 AIDL 实现互斥。
7. 空调页不是标准浮窗：公开 Global 状态值 `1/3` 及未知状态均隐藏顶栏和壁纸歌词；只有完全收起值 `2` 才允许恢复。关闭后不保存或回放进入空调前的 presentation，也不设置延迟恢复窗口，而是立即把最新的启动器、`window_mode`、Dock、占用租约、设置页和用户偏好交给统一策略重新计算，避免短暂顶栏或旧裁剪状态闪现。
8. 原车底部 Dock 也不复用标准浮窗规则：左侧和中央展开不改变歌词；最右侧展开且当前为壁纸歌词时，下边界裁到其真实上沿上方 `16px`，收起后恢复。WebView 保持完整桌面布局高度，外层窗口负责裁剪，避免剩余区域触发重新排版；桌面 alpha mask 的底部终点必须随外层裁剪边界移动，不能留在原完整窗口底部。

### 3.3 壁纸歌词边缘渐隐

1. 壁纸歌词的上下边缘使用 D 级项目适配：只在当前歌词可视容器上下各 `64px` 内由透明线性过渡到完全不透明，中部保持原始文字、阴影与虚化效果；Dock 裁剪时底部带随裁剪后的真实底边移动。不得给壁纸叠加黑色、白色或主题色渐变。
2. 渐隐必须由一张 CSS alpha mask 完成。外层几何发生离散裁剪时，原生层只写入一次可见高度比例以移动该 mask 的底部终点；不新增 JavaScript 帧循环、逐行坐标测量、截图采样、实时模糊、`backdrop-filter` 或动画 mask，也不得为了渐隐声明额外 `will-change` 常驻层。
3. 该 mask 只在桌面歌词表面启用。顶栏使用独立紧凑歌词容器，必须保持无 mask；当前行滚动定位、逐行切换和顶栏横向滚动不因边缘渐隐改变。
4. 车机验收除截图观感外，还需确认歌词静止时不产生持续刷新、只有一个 Overlay、无 WebView 致命日志；同长度改动前后采样不得出现明确的帧耗时回退。

## 4. 全局基础与提升规则

1. 原车 MBUI 资源库提供 `6 / 12 / 18 / 24 / 36 / 42 / 48 / 60 / 84px` 基础间距序列；当前设置页和应用中心实际重复使用了其中的 `18 / 42 / 84px`。其余数值先作为可选基础 token，不得只凭资源存在写入具体页面；应用中心的 `10 / 20 / 46 / 82px` 等专用值也不能反向提升为全局间距。
2. 已在设置页控件和应用中心顶部标签重复验证的标准中型高度为 `84px`；它可用于分段控件、导航选择和顶部标签触控层，但不意味着所有卡片或列表项都必须为 `84px`。
3. MBUI 资源库定义 Headline `48px`、Subtitle `36px`、Body1 `28px`、Body2/Caption1 `24px`、Caption2 `20px`；设置页已实际绑定 `28 / 24 / 20px`。应用中心另有页面专用字号 `21 / 25 / 18px`，必须留在该页面模式内。
4. MBUI 资源库定义默认圆角 `18px`、卡片圆角 `16px`、大圆角 `24px`；这些只是候选基础 token，只有具体控件形成绑定或截图边界能证明时才采用。
5. 字重、选中态与字号各有职责：字号表达层级，字重表达当前标签或重点，颜色表达状态；禁止同时放大、加粗、换色制造未经原车验证的第三套层级。
6. 深浅主题是语义资源集合，不是全局统一底色。主文字、次要文字和未选文字可以作为跨页面语义；根背景、卡片底色与透明度只有在多页面资源绑定和运行态都相同时才能提升为全局 token。
7. 每新增一个原车参考页面，必须从页面根布局追到实际主题属性和 day/night drawable，并记录运行态窗口与最终控件边界。截图只能验证合成观感，不能代替资源绑定。
8. 只有同一数值或语义在至少两个独立页面中同时得到 A 级资源证据与 B/C 级运行态证据，才允许提升为全局规则；否则保留在对应页面模式。

## 5. 页面模式 A：设置双栏

### 5.1 原车几何真值

1. 原车设置根布局通过 `mbui_skin_background -> ?layout_app_carset_bg` 绑定 `layout_app_carset_bg_day/night`。资产为 `2460 x 1620 px`，对应窗口的 2 倍尺寸；左右背景分界位于资产 `x = 600`，即实机约 `300px`。
2. 左侧菜单项宽 `252px`，左右边距各 `26px`，菜单占位约 `304px`；菜单选中项与中型控件同为约 `84px` 高。
3. 内容滚动层左 padding 为 `42px`、右 padding 为 `18px`，页面根容器另有右 padding `18px`；全宽控件最终距窗口右缘约 `36px`。顶部和底部 padding 均为 `42px`。
4. 标准分段控件高 `84px`、内 padding `6px`、外圆角 `18px`、选中块圆角 `12px`。
5. 标准间距序列为 `18 / 24 / 35 / 42px`，不得在布局中随意派生近似常量。
6. 原车布局最终绑定 `com.mbuiteam.mbui.widget.compoundButton.MBSwitch`。控件为 `64 x 36px`，thumb drawable 外框为 `30 x 30px`，其中 `8px` 透明 stroke 形成约 `22px` 白色核心；开关设置卡高 `126px`，半宽卡约 `411px`。
7. 原车文字层级为 Body1 `28px`、Body2/Caption1 `24px`、Caption2 `20px`。字重由层级表达，不能用额外字号制造第二套层级。

### 5.2 `03lyrics` 设置页布局规格

1. 页面采用稳定双栏：左侧类别导航、右侧设置内容。当前左侧按“歌词设置 / 服务状态 / 歌词缓存 / 歌词查找 / 权益中心”排列，在同一 Activity 内切换右侧内容，不新增独立页面；五个 `95dp` 导航行沿用原字号和图标尺寸，不压缩触控层。
2. 左栏宽 `345dp`，在目标车机约为 `304px`。这属于 D 级适配：覆盖原车约 `300px` 背景分界和 `304px` 菜单占位，同时容纳“03歌词”标题与权益角标。
3. 左栏内边距 `29.5dp`，菜单项 `286 x 95dp`；右侧内容 padding 为左 `48dp`、右 `41dp`、上下 `48dp`。
4. “歌词设置”固定为三个板块：
   1. “顶栏歌词”不显示板块简介，包含“歌词行数：一行 / 两行”和独立“歌词字号：小 / 标准 / 大”。
   2. “壁纸歌词”标题下固定显示“仅在壁纸模式下生效。”，包含启用、独立字号、歌词模糊、歌词阴影、歌词排版“密集 / 标准 / 宽松”和歌词焦点“顶部 / 中间”。
   3. “通用”包含“开机自启动 / 逐句翻译”两张开关卡；逐句翻译默认开启。所有开关都必须保留标题下的任务说明。
5. “服务状态”包含当前“悬浮歌词服务”运行开关和“重启悬浮歌词”。重启使用刷新动作图标和占满右侧可用内容宽度的整行操作卡，不伪装成持久布尔设置；页面不展示无法在目标固件中操作的系统授权入口。
6. “歌词缓存”使用全宽概览卡显示逻辑占用 / `128 MiB`、歌曲数量和按当前平均条目大小估算的剩余可缓存歌曲数；当前歌曲卡依次显示播放身份、来源、候选版本、自动 / 手动、翻译和更新时间；删除当前歌曲缓存使用全宽动作卡，人工覆盖存在时再显示全宽“恢复自动匹配”。缓存达到总预算后自动淘汰旧项，不提供清空全部入口。
7. “歌词查找”顶部使用单行紧凑工具条：歌曲名、歌手、专辑三个输入框和搜索动作同高并排；工具条下方用稳定两行结果项显示歌曲 / 来源 / 时长及歌手 / 专辑。结果最多 `24` 项，随右侧统一滚动容器滚动，不拆成多行表单或五列表格。
8. 分段轨道高 `95dp`、内 padding `7dp`、外圆角 `20dp`、选中块圆角 `14dp`；组标题到控件 `20dp`，组间距 `40dp`。
9. 开关卡为 `466 x 143dp`，同组两张半宽卡间距 `29dp`，开关约 `73 x 41dp`；目标车机物理尺寸分别约为 `411 x 126px`、`26px` 间距和 `64 x 36px` 开关。项目控件按原车 `64:36` 坐标空间绘制，白色滑块核心约 `22px`，不再让 `SwitchCompat` 叠加内部 inset 或缩放。
10. Body1 为 `31.75sp`、Body2 为 `27.25sp`、Caption2 为 `22.75sp`；在字体缩放 `1.0` 的目标车机分别渲染为约 `28 / 24 / 20px`。
11. 固定控件必须使用集中 `dimens.xml` 和样式资源；选中状态、字重或文案变化不能推动其他控件。
12. 左栏“03歌词”使用 `36sp` 标题层级并保持标题自身水平居中；权益状态使用约 `52 x 26dp` 固定角标放在标题右侧。目标车机上标题实际字形底边与 TextView 底边相差 `7px`，角标在布局底边对齐后再上移 `8dp`，使角标底框与标题实际字形同为屏幕 `y = 184px`；`16sp` 文案与小背景共同表达状态，不采用按钮语义。试用为浅蓝、过期为灰白、Pro 为金黄。

3. 卡片文字区宽 `200px`，位于卡片局部 `x = 155px`，顶部 `50px`；右侧预留 `10px`。标题 `25px`，说明 `18px`，两者间距 `3px`。
4. 场景卡的圆形插画、渐变底图和具体主题图属于原车专有视觉资产，不复制到项目。项目若采用此模式，应保留“左侧强识别图形 + 右侧标题/说明”的信息结构，并使用自有资源。
5. 场景是可直接执行的高影响动作时，标题必须说明任务，说明文字必须说明结果或边界；不能用纯氛围命名替代实际行为，也不能无确认复刻原车车辆控制能力。

### 6.5 页面模式 B 的项目复用边界

1. 只有当 `03lyrics` 后续出现需要在同一浮窗中切换两类同级内容的真实需求时，才采用顶部标签；当前设置页只有一个类别时仍遵循已验收的设置双栏，不为追求新样式改造成应用网格。
2. 应用图标网格只适合一组地位平等、以图标识别和直接启动为主的对象；设置值、布尔项或三档选项仍使用分段控件、开关和设置卡。
3. 智能场景卡只适合“一个入口对应一个完整任务”的对象；不能把普通设置项包装成插画卡，也不能嵌套卡片。
4. 根背景由页面模式 owner 统一提供，子 fragment 不再叠加一层整面背景；深浅资源必须成对定义，并在目标底图上验证合成观感。
5. 若未来实现页面模式 B，项目仍需使用标准 Android `dp/sp`、自有 drawable 与可访问控件，不依赖原车 APK、MBUI 私有类、系统签名或车辆控制权限。

## 7. 跨页面设计决策流程

1. 先识别任务：设置、对象启动、任务场景、信息浏览或歌词呈现；任务类型决定页面模式，不能先选画面再硬塞内容。
2. 再选择已验证模式：设置使用模式 A；同级内容切换且含大量对象时才考虑模式 B；没有匹配模式时继续取证，不凭相似截图拼装新模式。
3. 为每个页面建立独立绑定表：根布局、主题属性、day/night drawable、窗口边界、内容边界、文字 token、交互状态。
4. 实现时只复用已经提升为全局的基础 token和该页面模式自己的 token；任何跨模式复用都要能指出证据来源。
5. 验证时在同一主题、同一底图、相邻时间采集原车与项目截图，并用运行态边界确认尺寸；半透明背景必须以源 ARGB 与合成结果共同验收。

## 8. 规范维护与验收

1. 新增页面取证必须记录包身份、版本、APK 哈希、根布局绑定、深浅主题状态、运行态窗口与截图时间；无效混合主题截图不得进入正式结论。
2. 几何结论优先级为资源布局声明 + 运行态视图树，其次才是截图像素测量；颜色结论优先级为实际绑定资产或颜色资源，截图只验证最终观感。
3. 每次规范升级必须检查是否错误地把页面专用背景、透明度、字号、网格或卡片提升为全局规则。
4. 本轮有效应用中心基准已验证：浅色时 Android `uiMode` 与厂商主题均为浅色，`com.android.launcherMB` 以 `themeId = 32_0` 初始化；深色恢复后原车显示模式为“深色”、`Night mode: yes`、持久化主题为 `32_2`，应用中心接收 `32_2` 并以深色背景呈现。
5. 文档变更必须通过项目文档检查、Skill 检查和 `git diff --check`；纯规范施工不触发 Android 构建、安装或应用数据变更。若同轮把规范落实到 Android 窗口或资源，则必须继续执行构建、保留数据覆盖安装和对应运行级 smoke。
