# 安全规则

1. 触发条件：新增配置或环境信息。动作：可提交示例只保留占位符，真实路径、地址和凭证放被忽略的本机文件。验证：`git check-ignore` 和暂存前敏感信息扫描。边界：客户端必需的公开常量与机密分开判断。
2. 触发条件：新增 Android 权限。动作：同步 Manifest、产品价值、隐私说明和运行验证。验证：权限授予/拒绝路径 smoke。边界：与歌词主链无关的高风险权限不得加入。
3. 触发条件：处理外部服务数据。动作：只发送完成歌词匹配所需的歌曲元数据，不增加自建遥测。验证：请求构造和隐私文档核对。边界：不上传完整播放历史。
4. 触发条件：发布或重新授权。动作：先确认上游许可、来源说明和签名权利。验证：人工门禁。边界：技术上可推送不等于具备公开发布权利。
5. 触发条件：需求要求普通 Android APK 在安装后自行开启通知监听、悬浮窗或其他特殊系统访问。动作：先区分普通分发与平台签名/特权系统组件发行；普通 APK 只能引导系统授权，零点击版本必须由系统镜像或受控特权安装器配置授权。验证：以非开发机上的全新目标设备验证实际授权状态，不能用 ADB 临时状态代替。边界：不得通过应用代码、隐藏入口或开发调试命令宣称已绕过 Android 授权模型。
6. 触发条件：为窗口避让引入无障碍服务。动作：在配置、代码和说明三层同时限定目标包、事件类型和只读数据，系统授权页明确说明用途；不可用时保守缩小显示区域。验证：静态检查无动作/手势能力，实机确认既有无障碍列表不被覆盖、目标服务已连接且只响应目标窗口。边界：不得读取节点文字、模拟点击/手势、跨包扫描、轮询窗口或把无障碍扩展为通用前台应用监控。
7. 触发条件：受商业许可证控制的前台服务会长期持有可见窗口、媒体监听或其它运行资源。动作：用单一运行时访问守卫缓存统一验签门禁已经返回的 `Allowed?`，资源创建与可见更新只接受当前许可；到签名终点重读同一门禁，denied 先清许可再释放资源，新许可证只能通过验签持久化后替换。验证：纯规则覆盖有限、已到期、续签替换与无终点边界，运行级 smoke 覆盖撤销先于错误态展示、已有资源遇到 denied 立即退出。边界：远端未知状态仍按签名许可证有效期与明确离线宽限工作，不用 UI 状态、独立布尔值或高频联网轮询冒充云端真值。
8. 触发条件：较低层级无法覆盖，且需要运行会进入目标应用进程的商业 instrumentation。动作：优先使用可清状态的一次性模拟器或独立测试设备；文件、数据库、安全存储、设备身份和测试签名器必须显式注入独立命名空间，主机事务脚本保证失败路径仍尝试专用清场、卸载辅助包和恢复正式应用。验证：测试前后比对正式受保护记录的文件集合与哈希，确认测试前缀记录、辅助包和 instrumentation 注册均为空。边界：商业 instrumentation 不属于普通收尾；用户日常车机默认禁止，例外必须取得当次明确授权并通过独立 serial 与脚本确认参数，长期设备不得清正式数据来弥补隔离不足。
9. 触发条件：设备端需要自动刷新有离线宽限的签名商业许可证。动作：把签名 `expiresAt` 作为自动续签点、`offlineGraceUntil` 作为唯一最终离线终点；续签点前只读本地，连续服务只安排一个本地回调，瞬时失败只记录不早于 `24h` 的下一次自动尝试并重排一次，用户主动复核绕过冷却且继续复用单飞请求。验证：纯规则覆盖续签点前 / 到点 / 冷却边界 / 本地缺失和同一回调只触发一次，协议 fixture 覆盖到点失败后本地保持与冷却结束后的权威撤销。边界：冷却只控制网络负载，不得延长签名时间、覆盖撤销、阻断首次试用或替代运行时最终门禁；不得为续签引入轮询、WorkManager 或常驻线程。
10. 触发条件：为普通 Android Release 增加不依赖商业加固壳的基础抗重打包能力。动作：构建期启用 R8 优化、混淆与资源收缩，非 fixture 运行时只读取一次当前 APK signer 并与构建注入的公开摘要匹配；商业运行时配置不完整或 signer 不匹配即 fail closed。验证：实际执行 Release R8 / shrink 构建、检查 mapping 产出，并用纯规则覆盖摘要格式与不匹配。边界：签名摘要和许可证公钥不是秘密；不引入 APK 全量哈希、常驻反调试、Root / Hook 轮询或对已签名 APK 的二次处理。
