# AI 协作规则

1. 触发条件：进入新对话。动作：先读根 `AGENTS.md` 和 `docs/README.md`，再按任务路由加载最小上下文。验证：方案和施工能引用当前源码 owner 与验证入口。边界：不一次性加载全部文档制造噪音。
2. 触发条件：磁盘源码与旧文案、README、截图或终端显示冲突。动作：以源码为真值并同步文档。验证：源文件编码和实际构建。边界：不凭乱码或记忆重建中文内容。
3. 触发条件：同类判断重复出现。动作：使用 `rule-discovery` 沉淀规则、脚本、测试或 Skill。验证：后续入口能找到该能力。边界：一次性判断不升级为长期规则。
4. 触发条件：Android 施工完成准备交付。动作：使用 `task-closeout` 自动完成本机最短验证、保留数据覆盖安装、最简车机 smoke、进度与 Git 状态汇总，再交给用户主测。验证：安装、启动、进程/版本、致命日志和本次功能最小闭环通过。边界：不自动清数据、卸载、重启、提交、推送或发布。
5. 触发条件：发现跨项目通用能力。动作：使用 `template-feedback` 去专有化回流 `NewProject`。验证：模板源和当前项目各自检查通过。边界：不得把 `03lyrics` 的车型、坐标或业务事实污染模板。
6. 触发条件：用户下达普通功能施工且未明确要求完整代测。动作：按敏捷模式直接完成根因级实现，执行最短本机验证、自动覆盖安装和最简车机 smoke，再把主要实机场景整理为精确测试清单交给用户。验证：本机产物与最小运行闭环均通过，已验证与用户主测边界清楚。边界：敏捷不等于临时 Hack；安全、签名、数据迁移、发布或用户明确要求全量验证时不得套用最小验证。
7. 触发条件：用户完成主测。动作：有问题则继续修复并重新走自动安装验证；无问题则等待用户明确下达提交指令后再暂存和提交。验证：提交范围与用户确认过的实现一致。边界：用户只反馈“没问题”不等于授权提交、推送或发布。
