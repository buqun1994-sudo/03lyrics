# 验证规则

1. 触发条件：普通代码或工程行为变化，且用户未要求完整代测。动作：执行能发现本次改动语法、资源或直接逻辑错误的最短本机检查，再自动保留数据覆盖安装 debug APK。验证：本机产物与车机安装均成功。边界：不默认串行追加全量单测和 lint；最短检查必须覆盖本次变更的实际产物。
2. 触发条件：UI、悬浮窗、启动、MediaSession、开机恢复或车机状态变化。动作：安装后由 AI 先执行启动、进程/版本、致命日志和本次功能直接相关的最简 smoke，通过后再把剩余真实场景压缩为明确动作交给用户。验证：自动 smoke 证据与用户后续反馈。边界：不自动清数据、卸载或重启；不得把尚未执行的用户主测项表述为已通过。
3. 触发条件：测试失败。动作：定位真实根因，不降低断言或删用例换取通过。验证：修复后相关用例和回归用例均通过。边界：外部网络不稳定必须与纯逻辑测试分离。
4. 触发条件：文档、Skill 或脚本变化。动作：执行项目文档检查、Skill 检查和 `git diff --check`。验证：所有检查退出码为 0。边界：本机私有上下文不进入 Git diff。
5. 触发条件：安全、签名、数据迁移、发布链路或用户明确要求完整验证。动作：按风险扩展相关测试、lint、构建和运行验证，不套用敏捷最小集。验证：高风险边界逐项有证据。边界：普通 debug 覆盖安装仍可执行；签名、清数据、提交、推送或发布不得自行执行。
6. 触发条件：需要在保留应用数据和外部授权的物理车机上执行 instrumentation，或当前 ADB 同时连接多台设备。动作：禁止直接运行 Gradle `connected*AndroidTest`；先构建 debug 与 androidTest APK，再通过 `.codex/local-context.properties` 的目标 serial 使用 `adb -s` 做保留数据安装和定向 `am instrument`，结束后重新运行正式包安装 smoke。验证：测试只命中目标 serial，测试前后悬浮 AppOp、通知监听授权和应用偏好不变，正式包 smoke 通过。边界：只有唯一连接且允许清除状态的专用模拟器或一次性测试设备，才可直接使用 `connected*AndroidTest`。
7. 触发条件：准备向保留状态的物理车机安装 androidTest APK，尤其是应用或测试包曾发生签名迁移。动作：安装前只读提取车机正式包、车机已有测试包、新正式包和新测试包的证书摘要；正式包必须与新正式包同签名，新测试包必须同时与正式包及已有测试包同签名，任一不一致立即停止。验证：所有参与覆盖安装的证书摘要一致，`adb install -r` 成功且定向 instrumentation 后正式包 smoke 通过。边界：测试包证书冲突也不得自动卸载、清数据或换包名绕过；本机没有可信同签名构建入口时记录阻断并等待用户授权或配置恢复。
8. 触发条件：修复歌词搜索词、来源解析、近似匹配或网络调度问题。动作：除候选规则单测外，必须用来源真实字段结构覆盖“搜索计划 → 协议解析 → 候选裁决 → 正文结果”完整闭环，并至少保留一个相近错误候选反例；公网只用于显式网络 smoke，不能替代确定性 fixture。验证：计划、协议、编排和反例测试均通过，目标歌曲再执行受控网络 smoke。边界：不把单个歌曲或人物写入生产特判表；外部服务临时变化不得通过放宽硬边界来掩盖。
