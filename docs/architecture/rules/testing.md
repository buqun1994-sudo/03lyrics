# 验证规则

1. 触发条件：普通代码或工程行为变化，且用户未要求完整代测。动作：执行能发现本次改动语法、资源或直接逻辑错误的最短本机检查，再自动保留数据覆盖安装 debug APK。验证：本机产物与车机安装均成功。边界：不默认串行追加全量单测和 lint；最短检查必须覆盖本次变更的实际产物。
2. 触发条件：UI、悬浮窗、启动、MediaSession、开机恢复或车机状态变化。动作：安装后由 AI 先执行启动、进程/版本、致命日志和本次功能直接相关的最简 smoke，通过后再把剩余真实场景压缩为明确动作交给用户。验证：自动 smoke 证据与用户后续反馈。边界：不自动清数据、卸载或重启；不得把尚未执行的用户主测项表述为已通过。
3. 触发条件：测试失败。动作：定位真实根因，不降低断言或删用例换取通过。验证：修复后相关用例和回归用例均通过。边界：外部网络不稳定必须与纯逻辑测试分离。
4. 触发条件：文档、Skill 或脚本变化。动作：执行项目文档检查、Skill 检查和 `git diff --check`。验证：所有检查退出码为 0。边界：本机私有上下文不进入 Git diff。
5. 触发条件：安全、签名、数据迁移、发布链路或用户明确要求完整验证。动作：按风险扩展相关测试、lint、构建和运行验证，不套用敏捷最小集。验证：高风险边界逐项有证据。边界：普通 debug 覆盖安装仍可执行；签名、清数据、提交、推送或发布不得自行执行。
6. 触发条件：较低层级无法覆盖且确需运行 Android instrumentation。动作：优先使用唯一连接、允许清状态的一次性模拟器；物理设备必须是通过 `COMMERCIAL_TEST_ADB_SERIAL` 独立配置的专用测试设备，禁止直接运行会枚举全部在线设备的 Gradle `connected*AndroidTest`。验证：测试只命中独立目标 serial，测试辅助包和状态最终清空。边界：用户日常车机不属于默认测试设备；不得复用 `VEHICLE_ADB_SERIAL` 静默运行。
7. 触发条件：已经取得设备范围授权并准备向保留状态的物理测试设备安装 androidTest APK，尤其是应用或测试包曾发生签名迁移。动作：安装前只读提取设备正式包、已有测试包、新正式包和新测试包的证书摘要；正式包必须与新正式包同签名，新测试包必须同时与正式包及已有测试包同签名，任一不一致立即停止。验证：所有参与覆盖安装的证书摘要一致，`adb install -r` 成功且定向 instrumentation 后正式包 smoke 通过。边界：测试包证书冲突也不得自动卸载、清数据或换包名绕过；本机没有可信同签名构建入口时记录阻断并等待用户授权或配置恢复。
8. 触发条件：修复歌词搜索词、来源解析、近似匹配或网络调度问题。动作：除候选规则单测外，必须用来源真实字段结构覆盖“搜索计划 → 协议解析 → 候选裁决 → 正文结果”完整闭环，并至少保留一个相近错误候选反例；公网只用于显式网络 smoke，不能替代确定性 fixture。验证：计划、协议、编排和反例测试均通过，目标歌曲再执行受控网络 smoke。边界：不把单个歌曲或人物写入生产特判表；外部服务临时变化不得通过放宽硬边界来掩盖。
9. 触发条件：用户已明确授权在保留状态的物理测试设备运行 instrumentation，且目标应用自身存在已启用的无障碍服务。动作：测试前先确认目标服务拥有自己的有效 `ServiceRecord`，只从授权列表暂时移除该组件，并等待目标记录和连接完全消失后再启动 instrumentation；测试完成后先启动目标应用解除 stopped 状态，再恢复该组件并验证真实绑定。禁止用额外 `force-stop` 代替状态稳定。验证：其它无障碍组件前后不丢失，目标服务最终记录包含 `requested=true received=true hasBound=true`，且不存在目标 `DEAD ConnectionRecord`。边界：本规则只处理已获授权的例外，不构成日常车机测试许可；已有 DEAD 连接时必须停止，不得自动重启设备。
10. 触发条件：修改商业权益、许可证、设备身份或安全存储。动作：默认运行与改动直接相关的 JVM 测试、必要的 lint / 构建、保留数据安装与最简运行 smoke；只有修改直接触及 instrumentation 隔离或 AndroidKeyStore 真机行为且 JVM 无法覆盖时，才升级为商业 instrumentation。验证：默认闭环不安装 androidTest APK、不暂停无障碍、不强制结束应用；升级测试时由独立测试设备门禁和清场证据共同通过。边界：高风险改动不自动等于高破坏性测试，用户日常车机必须取得当次明确授权并传入脚本显式确认参数。
11. 触发条件：修改 MediaSession 元数据归一、选择、媒体通道接入或播放时间线。动作：先用目标设备的只读 `dumpsys media_session` 建立实际会话矩阵，再以纯规则测试覆盖标准描述优先、动态原始标题不推进录音代际、字段延迟补齐、`2000ms` 时长查询修订阈值、包名无关准入、语音 / 提示音排除、播放 / 缓冲 / 暂停优先级、停止 / 消失后不回接无关暂停会话、会话消失重选、零值或未来时间戳、未知位置、暂停冻结、seek 和时长封顶；设置页相关验证还必须覆盖不重启应用切换来源后，状态请求和人工查找字段不保留旧来源、不出现歌词正文或制作信息。随后执行 `testDebugUnitTest assembleDebug`、保留数据覆盖安装和最简启动 / 日志 smoke；当前曲目稳定播放时另观察至少 `30s`，不得出现录音代际抖动或重复查词。验证：矩阵至少包含已观测蓝牙、本机、U 盘、车机内置在线媒体及一个其它公开媒体会话；每个通道记录会话组件、状态、归一元数据、歌词显示和切换证据。边界：禁止用包名白名单测试代替真实能力验证，禁止为了构造播放状态而修改车机媒体数据库、注入私有广播或运行音频录制。
