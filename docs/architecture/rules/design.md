# 设计规则

1. 触发条件：调整顶栏歌词。动作：使用固定 `1920 x 1080` 设计空间和已验证安全边界，动态内容不得推动原厂控件。验证：五类图标组合、长歌词和一/两行截图。边界：未知图标不猜测占位。
2. 触发条件：调整桌面歌词。动作：歌词区域限定在架构总纲的桌面矩形内，设置页打开时临时回到顶栏策略。验证：壁纸、地图、设置页切换 smoke。边界：不覆盖状态栏和安全界面。
3. 触发条件：新增用户可见状态。动作：用用户能理解的任务、结果和下一步表达，补齐空态、加载态、失败态与权限态。验证：目标车机真实分辨率截图。边界：不在界面解释内部实现或调试参数。
4. 触发条件：新增动画或视觉效果。动作：优先低成本、不引起布局跳动的实现。验证：车机运行时观察帧率和交互。边界：禁用实时模糊、持续截图和高频装饰动画。
5. 触发条件：调整原生设置页。动作：按 `iCAR车机UI设计规范.md` 的“页面模式 A”保留左侧类别导航和右侧内容的双栏层级；当前已暴露设置项较少时，仍以未来类别扩展为边界，不得压缩成无导航的单栏卡片页。左栏与右侧内容面直接相邻，不能添加第三个空白或叠色层；左栏有效 alpha 低于右侧内容面，项目根容器和窗口背景必须透明。验证：目标车机深浅主题截图、选中态与开关交互 smoke。边界：不复制原车资产或控件库，不引入只为视觉存在的系统权限。
6. 触发条件：设置页需要强调色。动作：只读监听 `com.mb.provider.theme_key`，通过 `IcarThemeColorPalette` 统一映射选中和开启态，并按亮度选择前景色。验证：当前主题键、未知键回退和亮色主题前景对比单测，目标车机截图；当前用户主测结论为主题色未适配成功，在重新施工并通过实机验收前不得写成已完成功能。边界：不写系统设置，不把主题色键作为深浅主题来源，不在服务或 WebView 复制映射。
7. 触发条件：从原车页面沉淀或更新视觉规格。动作：先把证据分成原车资源真值、系统运行态、截图测量和项目适配；半透明页面必须从主题和根布局追到实际背景 drawable，通用颜色 token 只有形成运行布局绑定链后才能采用。原车物理 `px` 必须按目标设备密度换算为项目 `dp/sp` 后集中写入资源，禁止数值直抄。验证：记录根布局绑定、源资产 ARGB、密度公式，并在同一主题和同一底图上连续采集“无窗口底图、原车窗口、候选窗口”，以 alpha 合成结果复核截图。边界：无法证明绑定的资源只记录为候选，不进入正式色板；截图合成色不得回写为源色，也不能把底层、根背景和分区控件色误当成可任意叠加的独立层。
8. 触发条件：从第二个及后续原车页面扩展车机设计规范。动作：为每个页面分别记录根布局、主题属性、day/night 背景、窗口与内容边界；只有同一数值或语义在至少两个独立页面中同时获得资源绑定和运行态证据，才能提升为全局 token。验证：逐页检查背景引用链和运行态视图树，并确认深浅截图不是标准 `uiMode` 与厂商皮肤不一致的混合状态。边界：设置页双栏透明度、应用中心整窗背景、页面专用字号和网格间距默认互不继承；未形成运行态绑定的资源只作为候选记录。
9. 触发条件：新增或调整采用标准右侧浮窗模型的完整页面。动作：窗口固定沿用 `1230 x 810px` 运行态边界；在主题窗口层统一实现 `100%p -> 0 / 150ms` 的底部进入和 `0 -> 100%p / 300ms` 的向下退出，底层窗口静止，不叠加淡入淡出、缩放或内容层第二套位移。验证：车机录屏逐帧检查进入、系统返回和任务前后台路径，并复核静止窗口边界。边界：歌词悬浮层、Toast、局部弹窗和控件内部动画不套用整窗规则；系统未采用标准右侧浮窗模型时不得强改窗口尺寸。
10. 触发条件：在现有设置页新增菜单、状态或操作项，或修复已有开关的显示。动作：直接继承已经主测通过的双栏骨架、透明背景、间距和主题资源；若已获得原车控件最终布局绑定与物理尺寸，应按绑定链取证结果实现，而不是凭截图近似。原车 `MBSwitch` 固定为 `64 x 36px`、thumb 外框 `30px`、透明 stroke 后白色核心约 `22px`；当标准 Android 控件会再次套用内部 inset/缩放时，使用项目自有、实现标准 `Checkable` 与开关无障碍语义的控件复现参数。验证：构建安装后检查最终物理尺寸、checked 语义、卡片点击与主题色，并回归双栏、透明度与深浅主题。边界：不链接车厂私有类或资源 ID，不把一次性命令伪装成持久开关；同一规格已有 A/B/C 级证据时不重复取样，只有证据冲突或新增页面模式才重新取证。
11. 触发条件：设置页同时展示购买标题、折扣角标和原价 / 限时价等营销信息。动作：把标题、折扣和价格对比建模为一个视觉组；标题与折扣在同一上行紧邻，价格在下行对比，并让两行共用稳定的右边界；水平居中以整个视觉组的边界为准，不分别居中组内元素。存在独立顶部状态组和底部动作组时，营销组在两者之间的可用区垂直居中，不机械套用整页中心。跨权益与订单页面统一的是最外层板块到页面边缘的距离，不强制不同内部结构的主按钮重合；支付方式随订单支付组整体移动。验证：目标车机截图和 UI bounds 同时确认营销组水平中点、两行右缘、上下相邻间距，以及各页顶部 / 底部板块的边缘距离。边界：订单明细继续使用标签 / 值对齐，不套用营销组排版；动态价格和折扣只绑定服务端报价，不为视觉对齐硬编码金额或比例；错误提示只能向上扩展，不能推动支付组底边。
12. 触发条件：综合卡因进入权益页或 PRO 生效而从页面结构中 `GONE`，或权益状态从未购买切换为稳定 PRO。动作：综合卡隐藏只释放其占位，不代表后续内容可以贴顶；显示 / 系统页必须从综合卡下方的紧凑留白切换到标准页面顶部留白。PRO 权益页使用独立居中完成组，不复用试用 / 过期的顶部状态组；低成本的单一金色状态图标用于完成态点缀。验证：分别在综合卡可见 / 隐藏状态测量显示和系统内容顶部边界，并在 PRO 页同时核对完成组中心、旧状态组、营销和支付入口的可见性。边界：不为装饰引入位图、动画或第二套主题色；订单、二维码及未购买权益页继续使用各自已经验收的垂直结构。
13. 触发条件：外层窗口裁剪歌词、文本或其它带边缘渐隐的内容。动作：保留内层完整布局，使用离散几何状态把 alpha mask 的可见终点同步到外层实际边界，使该边界仍以既定宽度自然淡出。验证：分别核对完整与裁剪状态的内层高度不变、mask 终点、唯一窗口几何和实机截图。边界：不通过重排内容、透明遮罩叠层、持续动画、截图或逐帧坐标测量伪造渐隐；顶栏等未启用该 mask 的表面不继承此规则。
14. 触发条件：WebView 歌词换句动画涉及字号、模糊、阴影、颜色或其它会触发布局 / 栅格化的属性。动作：先一次性提交真实最终布局，再用 FLIP 只过渡 `transform` 与必要的 `opacity`；当前句可以拥有真实的大字号终态，模糊、阴影和 alpha mask 只作为离散静态样式切换。验证：生产 HTML 的真实 WebView 用例必须断言动画期间字号已经是最终值、过渡属性白名单和中断后样式清理；目标车机以同歌曲、同特效、同可见区域采样，`P90 <= 33.3ms`、`P95 <= 50ms`，`30fps` 录屏每次换句至少有 `5` 个单调位置且不连续冻结超过 `2` 帧。边界：不得用永久视觉缩放冒充最终字号，不对 `font-size`、`filter`、`text-shadow` 或 mask 做逐帧插值，不引入实时模糊、Canvas 重绘、持续截图或高频轮询。
