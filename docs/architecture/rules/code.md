# 代码规则

1. 触发条件：修改播放、窗口、表面或生命周期状态。动作：沿 `LyricsOverlayService` 单一协调主链施工，不在 Activity、Receiver 或 WebView 复制状态机。验证：相关单测、构建和实机状态切换。边界：纯 UI 样式可留在对应呈现层。
2. 触发条件：新增或修改歌词源、搜索词、候选规则或网络时序。动作：搜索变体集中在 `LyricsSearchPlanner`，第三方协议留在 `PublicLyricsSources`，每来源完成顺序与正文通道留在 `LyricsResolutionSession`，仓库只负责装配与封面，最新请求取消与一次瞬时失败重试留在 `LyricsResolutionCoordinator`，录音归一、证据和候选选择分别留在 `RecordingIdentity`、`RecordingEvidence` 和 `LyricsCandidateSelector`。目录来源只接收显式搜索请求；每来源最多三项，当前项无合格候选或正文为空时立即推进本来源下一项，不等待其它来源。标题、歌手、专辑统一输出带具体原因的完全一致、近似、未知、明确不一致四级证据；名称归一化只消除格式字符差异，空格、点、下划线、连字符及文字体系切换必须在压平文本前保留为有序分段。标题主体或歌手展示名的一方完整分段序列连续包含于另一方，或双方共享占主体的连续分段且剩余部分只是跨文字展示时，记为近似；分隔后的多段可以组合成连续主体，不得退化为无序单片段特判。无分隔的同文字任意字符子串和非连续拼接仍拒绝，展示分隔不自动改写为合作歌手。双方版本相同或都省略为完全一致，仅一侧标注版本为近似，双方明确版本冲突才是不一致并硬拒绝。时长和确认标题是硬门槛，歌手明确不一致一律拒绝，排序分不得充当安全准入；合格候选先按版本证据等级再按综合证据排序。独立来源只能补充未知证据，标题未知仍必须先有双语标题桥接。最多两条不同来源正文通道，首个有效同步歌词立即停止；LRCLIB 模糊列表只在 LRCLIB 精确请求与目录计划均已完成且无正文在途，或到达首轮截止时启动，并共享原总截止和正文通道。新播放请求必须断开旧连接，只有类型化瞬时失败可等待 `1000ms` 重试一次，禁止其它 `sleep` 或人为屏障。涉及语言版本的标准化只能遍历 ISO 语言集合，合作歌手括号不参与录音版本解析。验证：搜索计划顺序与上限、来源真实格式解析、完整“查询计划 → 协议解析 → 候选裁决 → 正文”闭环、本地化名称、轻微拼写、双语标题、有序分段连续包含、共享跨文字主体、无分隔子串、非连续分段、跨文字未知态、明确不同歌手、同源重复、单侧版本省略、明确版本冲突、合作歌手、括号分级、单来源、多发行、完成顺序、双正文通道、取消、截止、重试和目标车机网络 smoke。边界：不维护歌曲或人物特判表；UI 不解析第三方 JSON，也不得绕过原生选择主链直接请求歌词源。
3. 触发条件：修改车机状态。动作：`IcarDisplayStateMonitor` 保持只读、事件驱动和失败保守；未知值不得猜测为可见或桌面态。验证：纯状态单测和目标车机 smoke。边界：不得接入 CAN 或未经验证的私有写接口。
4. 触发条件：修改缓存、候选准入或用户人工选择歌词。动作：预算和淘汰阈值集中在 `LyricsCachePolicy`；自动缓存必须保存匹配策略版本及在线入选所需的最多两条支持候选，读取时用 `LyricsCandidateSelector` 重放完整证明，不得把在线共识降成单来源复核。人工选择可以不经过自动准入淘汰，但必须在独立表中绑定当前播放身份、只接受用户点选后取得的同步正文，不能伪造自动证明或反向放宽自动匹配；读取优先级由缓存 owner 固定为人工覆盖、自动缓存、在线自动匹配，恢复自动只删除人工覆盖。策略无法兼容旧载荷时显式升级数据库；新增独立能力时优先做保留已有安全缓存的增量迁移。验证：策略单测；SQLite 集成验证覆盖版本升级、错误项拒绝、证明序列化、双来源再次读取、人工优先、恢复自动和清理统计。边界：服务层只调用缓存接口，不复制缓存或候选规则；证明只复用已有目录元数据，不额外联网；人工搜索结果不得混入自动缓存表。
5. 触发条件：需要跨两个以上调用点复用规则。动作：回到现有 owner 或新增边界清晰的抽象。验证：调用点不再存在重复实现。边界：不为单次文案或样式新增抽象。
6. 触发条件：原厂窗口、Dock 或跨应用桌面面板影响歌词。动作：先把信号归类为“隐藏全部歌词 / 切顶栏 / 横移壁纸 / 只裁剪壁纸”四种不同效果，再由 `IcarLyricsPresentationPolicy` 按当前全部状态生成唯一 presentation；空调占用、未知和全屏独占租约优先隐藏，标准窗口与桌面区域租约切顶栏。左侧壁纸的 SR 横移先消费目标 Launcher 中 SR 把手相邻矩形的有方向位移提示，目标车机超过 `8px` 即触发，`window_mode` 仅作瞬时提示退场后的稳定兜底；固定动画为 `250ms` 三次贝塞尔 `(0.2, 0.8, 0.2, 1)`，不得跟随手势百分比。左侧原位采用左 Dock，被 SR 推开后采用中间 Dock，右侧位置始终采用右 Dock。跨应用状态必须由版本化 bound Service 的绑定存续表达：`ACQUIRE_OCCUPANCY_LEASE` 只表示桌面区域占用，`ACQUIRE_FULL_DISPLAY_OCCUPANCY_LEASE` 才表示全屏独占；不得用包名、前台扫描或无障碍扩大监听范围猜测状态。空调关闭或租约释放后不保存或回放旧 presentation，原厂状态分批恢复时每个事件仍只按最新状态重算唯一表面。外层裁剪不得截掉内层边缘语义，桌面 mask 的下端必须随可见高度离散更新。`IcarDisplayStateMonitor` 只读监听已验证的 Settings，`IcarDockAccessibilityService` 只读观察 Launcher 的 SR 把手和窗口边界，外部适配器都不直接操作歌词窗口。验证：空调 `1/2/3/未知`、关闭后最新窗口状态、SR 方向阈值与 `0/1/2/3/未知` 稳定兜底、左右位置镜像、`250ms` 位移契约、Dock 左/中/右与收起/展开/未知、实际位置裁剪后渐隐终点、两类租约、标准窗口和优先级矩阵纯规则测试，加目标车机逐项状态与唯一 Overlay smoke。边界：无障碍只允许目标 Launcher、窗口结构事件、SR 把手资源 ID 与矩形和窗口边界读取，不读文字、不执行节点动作或手势；不得写厂商设置、接私有窗口接口、轮询前台应用或把不同窗口一律简化成顶栏；跨应用租约不得暴露业务 Binder 方法或直接操作歌词窗口。
7. 触发条件：准备在目标车机设置页暴露系统敏感授权入口。动作：先分别验证任务栈、触摸输入和权限能力；当前固件的通知使用权页面会对根视图启用遮挡触摸过滤，而常驻全屏 `SYSTEM_ERROR` 窗口会使触摸被系统丢弃，因此应用设置页不得暴露该无效入口。验证：源码或 APK 行为取证、窗口层级与真实触摸结果交叉确认，并检查设置页不存在授权控件和系统授权 Intent。边界：不使用隐藏 API、私有系统组件、自绘授权页、ADB 运行依赖或应用侧权限伪造；授权只作为外部受控部署前置条件。
8. 触发条件：`BroadcastReceiver`、升级恢复或其它后台入口通过 `startForegroundService()` 创建歌词服务。动作：服务 `onCreate()` 必须先创建通知渠道并立即履行 `startForeground()`，之后才能读取特殊授权、创建运行资源、停止或进入恢复态；缺权时释放运行资源、保留用户自动恢复意图并用可观察恢复状态结束，只有明确用户停止动作可以清除该意图。验证：双授权、分别缺失授权和主动停止的纯决策单测，加目标车机缺权启动 `10` 秒日志、通知、服务与监听绑定 smoke。边界：不得用延迟任务、轮询、自拉活、后台弹页或应用侧自行授权替代前台服务契约与系统授权。
9. 触发条件：外部商业接口返回网关错误、HTML / 纯文本错误页或其它非 JSON `5xx`。动作：在 `DeviceCommerceJsonApi` 适配层统一映射为瞬时网络失败，让上层保留仍有效的本地许可证并按既有冷却 / 用户重试策略处理；本地验签明确已过期时保留 `Expired` 事实，不把它误报为未知网络错误；明确撤权、设备不匹配、验签和存储失败仍保持各自不可回退语义。验证：至少用 `HTTP 530` 加纯文本体、合法 JSON `5xx`、有效本地许可证、已过期本地许可证和明确 `entitlement_revoked` 各跑一次 API / 网关测试。边界：不因网关不可用伪造新许可证或把过期 / 无许可证状态变成有效。
10. 触发条件：接入、扩展或排查任一媒体播放器。动作：以公开 `MediaSessionManager` / `MediaController` 数据作为唯一播放入口，包名只用于排除本应用、诊断日志和已验证传输格式适配，不得作为播放器能力白名单；按 `USAGE_MEDIA`、内容类型、传输动作和标题等公开语义准入，明确排除语音 / 提示音；播放中优先于缓冲，随后保留系统返回的会话顺序，并为所有候选会话注册回调以便状态变化立即重选。元数据进入录音身份、设置、缓存或查词前必须由 `MediaSessionMetadataPolicy` 归一：`TITLE` 只解释为歌曲名，`ARTIST` 只解释为完整歌手名，`ALBUM` 只解释为专辑名；标准字段和 `MediaDescription` 仅按稳定优先级互为回退，`BLUETOOTH_AVRCP` 不改变这三个字段的语义，也不按连字符、展示文本或平台猜测边界。蓝牙传输只保留已验证的时长单位归一。任何歌词、制作信息或其它动态展示文本都不得成为切歌真值。`MediaRecordingStateTracker` 以会话 Token 和归一录音字段拥有唯一录音代际；来源或真实录音变化才推进代际，字段补齐以及已知时长相对上次查询累计变化超过 `2000ms` 只推进查询修订。设置页和 WebView 只消费服务下发的代际 / 修订，不自行拼接文本键或把媒体字段回传为查词真值。`AudioManager.AudioPlaybackCallback` 只能作为会话重读唤醒，禁止消费配置内容。设置打开、状态请求和人工媒体操作必须先同步重读会话，再发布或绑定歌曲身份。一个运行周期已经选中过来源后，停止 / 消失只允许清空当前来源，不得从无关暂停会话回接。标准会话进度必须由本地时间线 owner 归一：有效且不在未来的 `lastPositionUpdateTime` 才可锚定，零值 / 未来值 / 不变时间戳按回调时刻处理，`PLAYBACK_POSITION_UNKNOWN` 不得抹掉已建立进度，首次无可信位置时保持 `timelineReady=false`；蓝牙 AVRCP 只保留已验证的专用事件补偿，不把该分支复制给其它播放器。验证：元数据归一、稳定代际、选择策略和时间线异常边界的 JVM 测试，`assembleDebug`，以及目标车机逐项媒体会话 smoke。边界：不读取系统音频、不调用厂商私有播放器接口、不猜测包名、不增加与歌词无关权限；播放器未公开有效媒体语义时保持静默。
11. 触发条件：系统活动会话在 Android 10/11 因 `active=false` 未进入 `MediaSessionManager`，但公开蓝牙 Browser 服务仍发布同一 Token。动作：由 `BluetoothMediaBrowserSessionBridge` 动态查询 `android.media.browse.MediaBrowserService`，仅连接 `com.android.bluetooth` 的已导出已知服务；只在 A2DP / BLE 路由存在且系统列表没有蓝牙包时启用，控制器按 Token 去重后追加到既有选择主链。桥接器只拥有连接、画像、超时和一次退避重试，不拥有选歌、身份解析或歌词请求；迟到回调必须被 generation 丢弃，路由移除、会话销毁和服务停止必须断开。Android 9 A2DP 时长保持现有毫秒语义，Android 10/11 Browser 画像显式标记秒语义；`MediaSessionMetadataPolicy` 统一执行溢出安全转换、`reportedPositionMs` 证据和 `86_400_000ms` 上限。验证：Browser 服务发现、画像选择、Token 去重、超时 / 重试 / 挂起 / 断开和未知单位边界测试，并在 Android 9 与 Android 11 目标设备分别记录桥接状态；边界：不读取 `dumpsys`、通知正文、厂商私有接口，不改变 `MediaSessionSelectionPolicy` 的既有排序。
12. 触发条件：嵌入式权益查询、报价、建单或支付轮询可能与用户切换权益 / 订单 / 二维码页并发，或云端返回撤权。动作：`CommercialStateMachine` 记录唯一页面 owner，显式用户导航与当前支付操作优先于晚到异步结果；新 Activity 生命周期才清空 owner并允许恢复持久化待支付会话，权威 PRO / 拒绝结果仍可强制回权益页。撤权固定映射为可重新购买状态，清除旧报价后由“获取Pro”触发一次最新报价请求，成功才进入订单页，普通查询错误仍走“重新确认”。离开二维码页必须停止轮询并使旧代际结果失效；`MainActivity` 只把系统返回转发给商业页面，不复制状态判断。验证：状态机覆盖订单 / 二维码 owner、生命周期恢复、撤权、迟到快照 / 报价 / 建单 / 轮询，控制器测试覆盖撤权后重新报价，布局契约覆盖文案、按钮路由与返回入口，并用真实 staging 退款态完成车机 smoke。边界：不得从 UI 直接请求商业 API、恢复已撤销旧报价或绕过本地 fail-closed 门禁；fixture 结果不得替代 staging 退款验证。
