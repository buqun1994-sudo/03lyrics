# 03lyrics 项目长期总纲

## 1. 项目定位

1. `03lyrics` 是面向 iCAR 03 车机的轻量悬浮歌词应用。
2. 核心结果：从播放器公开的 Android MediaSession 获取播放信息，匹配同步歌词，并根据原厂桌面状态在顶栏或壁纸区域安全显示。
3. 正式运行不依赖 root、ADB、手机、电脑、自建后端或无障碍服务。
4. 本项目基于 `tcrrry/desktop-lyrics` 的历史继续适配；上游只作为来源追溯，当前默认远端为项目自己的 GitHub 仓库。

## 2. 平台基线

1. 目标车机：Android 9（系统 SDK 28）、`1920 x 1080`、型号标识 `S56_HQX`、高通 8155。
2. 工程基线：Kotlin Android，JDK 17，Gradle 8.2，Android Gradle Plugin 8.2.2，`compileSdk/targetSdk 34`，`minSdk 26`。
3. 当前应用身份：`applicationId/namespace = com.tcrrry.desktoplyrics`，`versionName = 1.14-icar03`，`versionCode = 114`。
4. 车机整体负载偏高，新增能力必须保持事件驱动、固定尺寸资源缓存和低绘制成本。

## 3. 物理主链

| 层级 | Owner | 职责与边界 |
|---|---|---|
| 设置入口 | `MainActivity.kt` | 读取和写入用户设置，向服务发送明确动作；不拥有播放或窗口状态机 |
| 系统授权入口 | `MediaListenerService.kt` | 提供 NotificationListenerService 绑定入口；不读取普通通知正文 |
| 应用流程 | `LyricsOverlayService.kt` | 前台服务、MediaSession、播放时间线、窗口生命周期、表面切换、WebView 桥接 |
| 车机适配器 | `IcarDisplayStateMonitor.kt` | 只读观察已验证的公开 Global Settings 和存储事件；输出纯显示状态 |
| 外部数据适配器 | `DirectLyricsRepository.kt` | 并发查询 LRCLIB、QQ 音乐、网易云并限制网络响应 |
| 领域选择规则 | `LyricsCandidateSelector` | 用标题版本、专辑、时长和必要时的直接歌手名核验候选录音；未知或竞争结果保持静默 |
| 本地基础设施 | `LyricsCache.kt` | SQLite 歌词缓存、使用频率与批量淘汰 |
| 开机恢复 | `BootReceiver.kt` | 仅在用户已启用自动恢复时启动前台服务 |
| 界面呈现 | `lyrics_overlay.html` | 顶栏/桌面歌词布局、逐行同步和 WebView 交互；主题由服务明确下发，不自行读取厂商状态 |
| 自动验证 | `app/src/test/` | 候选匹配、车机布局状态和缓存策略的 JVM 测试 |

## 4. 运行状态流

1. 用户启动悬浮歌词后，`LyricsOverlayService` 保存自动恢复意图、启动前台服务并注册 MediaSession 与车机状态监听。
2. 播放器变化经 MediaSession 回调进入服务；服务先查 `LyricsCache`，未命中或过期时调用 `DirectLyricsRepository`。
3. 外部来源并发返回候选，由 `LyricsCandidateSelector` 选择可信的同步歌词；无可信结果时不显示错误歌词。
4. `IcarDisplayStateMonitor` 把原厂启动器状态映射为 `DESKTOP` 或 `TOPBAR`，未知状态保守映射为 `TOPBAR`。
5. 服务根据用户“壁纸歌词”设置和设置页是否打开计算有效表面，更新 WindowManager 几何并通知 WebView。
6. 用户主动停止时清除自动恢复意图；开机或应用升级广播只有在该意图仍为真时才恢复服务。
7. Android 标准 `Configuration.uiMode` 是深浅主题唯一真值：设置页由 `values` / `values-night` 自动选色；常驻服务在配置变化时只向 WebView 下发 `light` / `dark`，不重载歌词页和播放时间线。

## 5. 已验证几何不变量

所有坐标以 `1920 x 1080` 设计空间表达，运行时按真实屏幕等比换算。

1. 桌面歌词区域：`x = 660..1890`，`y = 90..900`。
2. 顶栏歌词基线：右边界 `x = 881`；没有动态图标时左边界 `x = 321`，可用宽度 `560 px`。
3. 已确认动态图标包括行人提醒、无线充电、SD 卡/DVR、USB 存储和守护模式。
4. 每个确认可见图标占用 `75 px`（`42 px` 图标 + `33 px` 安全间距）；未知状态不占用宽度。
5. 顶栏歌词最小可用宽度为 `180 px`；不足时隐藏该表面，不覆盖不确定区域。
6. 表面模式只由启动器状态和用户显示策略决定；图标可见性只影响顶栏几何，不改变表面模式。

## 6. 歌词匹配与网络不变量

1. 歌词查询并发访问 LRCLIB、QQ 音乐和网易云；必须返回同步歌词才能进入最终歌词选择。
2. 正式歌词匹配只接受已知时长（至少 `1000 ms`）：标题基础名与版本标记必须一致，车机与候选时长差不得超过 `2000 ms`。
3. 车机与候选都给出有效专辑时，专辑标准化后必须一致；任一方专辑未知时，歌手标准化后必须直接一致。跨语言歌手展示不维护别名，也不单独否决已由标题、专辑和时长确认的候选。
4. 多个符合条件的候选必须仍描述同一版本；无法归为唯一版本时保持静默。查询分为目录召回（最多 `1800 ms`）与已确认候选歌词下载，总截止仍为 `3800 ms`；连接超时 `1500 ms`，读取超时 `2200 ms`，封面总截止 `3000 ms`，单响应最大 `2 MiB`。
5. 占位歌手、空内容、`null`、`[object Object]` 和普通无时间轴歌词不得进入顶栏同步歌词主链；WebView 不得绕过 `DirectLyricsRepository` 直接请求歌词源。

## 7. 缓存不变量

1. 缓存上限 `128 MiB`，触发清理后目标为上限的 `90%`，每批最多淘汰 `256` 条。
2. 缓存使用 SHA-256 的标准化“歌曲 + 歌手 + 专辑 + 候选录音时长（秒级）”身份作为 key；读取时只探测当前播放时长正负 `2` 秒内的 key，并再次核验实际时长。
3. `30` 天后允许刷新歌词；访问频率最多累计 `30` 次，每次为淘汰分增加 `7` 天权重。
4. 缓存策略只由 `LyricsCachePolicy` 管理，服务层不得复制阈值。

## 8. 绝对边界

1. 不把 `03桌面` 的应用抽屉、安装、卸载、快捷控制或右侧手势面板放进本项目。
2. 不写车辆状态，不连接 CAN，不调用未经独立验证的车厂私有控制接口。
3. 不使用 ADB、无障碍、轮询、持续截图或实时模糊支撑正式功能。
4. 不绕过 Android 原生权限、前台服务和悬浮窗机制。
5. 包名、签名和升级身份的变更必须先有独立迁移方案和实机升级验证。
6. 主题适配不依赖厂商私有主题键、截图、亮度推断或轮询；厂商键只可用于诊断，不得形成第二套主题状态机。
