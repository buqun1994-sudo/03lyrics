# 03lyrics 项目长期总纲

## 1. 项目定位

1. `03lyrics` 是面向 iCAR 03 车机的轻量悬浮歌词应用。
2. 核心结果：从播放器公开的 Android MediaSession 获取播放信息，匹配同步歌词，并根据原厂桌面状态在顶栏或壁纸区域安全显示。
3. 正式运行不依赖 root、ADB、手机、电脑或自建后端；仅最右侧 Dock 避让依赖用户或受控部署明确启用的只读无障碍服务，该服务不读取文字、不执行节点动作或手势。
4. 本项目基于 `tcrrry/desktop-lyrics` 的历史继续适配；上游只作为来源追溯，当前默认远端为项目自己的 GitHub 仓库。

## 2. 平台基线

1. 目标车机：Android 9（系统 SDK 28）、`1920 x 1080`、型号标识 `S56_HQX`、高通 8155。
2. 工程基线：Kotlin Android，JDK 17，Gradle 8.2，Android Gradle Plugin 8.2.2，`compileSdk/targetSdk 34`，`minSdk 26`。
3. 当前应用身份：`applicationId/namespace = com.tcrrry.desktoplyrics`，`versionName = 1.14-icar03`，`versionCode = 114`。
4. 车机整体负载偏高，新增能力必须保持事件驱动、固定尺寸资源缓存和低绘制成本。

## 4. 运行状态流

1. 任何由 `startForegroundService()` 创建的 `LyricsOverlayService` 都先创建通知渠道并立即调用 `startForeground()`；授权判断、运行资源创建、恢复退化、停止和异常处理全部发生在前台契约之后。
2. 服务集中读取启动来源、悬浮权限和通知使用权，并通过唯一启动策略进入 `RUNNING / RECOVERY / COMMERCIAL_RECOVERY / USER_STOPPED`；日志只记录判定字段和最终状态，不记录媒体内容或用户数据。
3. 两项授权有效时清除旧恢复通知并沿唯一服务实例启动 MediaSession、车机监听和唯一 WebView/窗口。任一授权缺失时释放歌词运行资源、结束前台服务且返回 `START_NOT_STICKY`，保留 `PREF_AUTO_START`，并留下可点击进入现有 `MainActivity` 的常驻恢复通知；下一次授权有效的合法启动会清除该通知并重新进入同一运行主链。
4. 播放器变化经 MediaSession 回调进入服务；服务立即取消上一首歌的请求，先查 `LyricsCache`，未命中或过期时交给 `LyricsResolutionCoordinator`。新请求、运行态重建和服务销毁都会取消旧连接，不只丢弃旧回调。
5. `LyricsResolutionSession` 按来源实际完成顺序把目录候选交给 `LyricsCandidateSelector`；某个目录来源当前查询没有可用候选时只推进该来源的下一项搜索计划，不等待其它慢来源。首个通过显式准入且正文为同步歌词的结果立即返回。无可信结果保持静默；仅瞬时网络、限流、服务端或截止失败等待 `1000ms` 后重试一次，完成无匹配和元数据无效不重试。
6. `IcarDisplayStateMonitor` 把原厂启动器状态映射为 `DESKTOP` 或 `TOPBAR`，并事件驱动监听 `window_mode`：`0/1` 表示桌面歌词区域无系统窗口冲突，`2/3` 包含标准浮窗冲突；其它值或读取失败保守映射为 `TOPBAR`。同一适配器监听 `global_setting_ac_page_status`：`1/3` 为占用，`2` 为完全收起，其它值或读取失败为未知；占用和未知均隐藏全部歌词。
7. `IcarDockAccessibilityService` 只在 Launcher 窗口或结构变化时读取交互窗口边界，事件以 `80ms` 合并并在 `320ms` 复核动画终态；分类器只识别屏幕右侧 `60%..75%` 起点、`25%..40%` 宽度且贴右下边界的窗口。`LyricsOverlayService` 将该状态与设置页、租约、启动器、标准窗口和用户偏好交给 `IcarLyricsPresentationPolicy` 全量重算：租约和标准浮窗切顶栏，右侧 Dock 只在壁纸表面裁剪下边界，空调页隐藏全部歌词，未知 Dock 在壁纸态保守切顶栏。空调关闭后不保存或回放旧 presentation，而是立即以最新原车窗口状态重算唯一表面。
8. 只有 `ACTION_STOP` 表示用户主动停止并清除自动恢复意图；授权失效只进入恢复态。开机或应用升级广播只有在该意图仍为真时才请求恢复服务。
9. Android 标准 `Configuration.uiMode` 是深浅主题唯一真值：设置页由 `values` / `values-night` 自动选色；常驻服务在配置变化时只向 WebView 下发 `light` / `dark`，不重载歌词页和播放时间线。
10. 设置页现有代码只读监听 `com.mb.provider.theme_key`，由 `IcarThemeColorPalette` 尝试映射原车色板；最新用户主测结论为主题色没有适配成功，因此该链路保持未完成状态，不改变深浅主题已经验收通过的结论，也不写车机设置或进入歌词服务、WebView 主链。
11. 设置页只在进入时通过 `NotificationManagerCompat.getEnabledListenerPackages()` 和 `Settings.canDrawOverlays()` 判断服务能否启动；“服务状态”页展示当前运行开关与一次性重启动作，不展示授权状态或跳转系统授权页。“开机自启动”是独立持久偏好，普通服务启动不得偷偷改写；`ACTION_STOP` 仍表示用户主动停止并清除该意图。当前目标固件的敏感设置页会过滤被常驻覆盖窗口遮挡的触摸，授权属于应用外部的受控部署前置条件；`MainActivity` 保持普通 `singleTop` 启动模式。
12. `ACTION_RESTART` 只由 `LyricsOverlayService` 处理：同一服务实例先使旧运行代际失效，再注销 MediaSession、音频、AVRCP 与车机状态监听，移除并销毁唯一 WebView/窗口，重新读取显示偏好并重建运行资源；不经过 `ACTION_STOP`，不改变 `PREF_AUTO_START`。
13. 顶栏当前行在 `lyrics_overlay.html` 内同时保存“显示索引”和“是否到达该行时间点”：下一句可沿用现有 `90ms` 提前量切入画面，但主行横向滚动资格只在原始时间戳到达后开放。第一句在前奏阶段只预览不滚动；跳播回时间点之前时，同一行关闭滚动资格并复位，调度器必须分别唤醒“提前切行”和“准确到点”两个事件。切行只允许重算新当前行的横向动画；退出行保持既有位移直至移除，避免长句从末尾反向回滚。
14. 顶栏与桌面歌词共用同一个原生悬浮窗根表面；表面切换由 `LyricsOverlayService` 唯一编排为旧表面 `120ms` 线性淡出、完全透明时提交窗口几何与 WebView 布局、新表面 `160ms` 线性淡入。动画期间窗口不可触摸，快速连续切换只允许最新目标完成回调；WebView 不维护第二套表面交接状态。
15. 桌面歌词的上下边缘渐隐归 `lyrics_overlay.html` 呈现层所有：只对桌面 `.lyrics-viewport` 使用 `64px` 线性 alpha mask，中部保持完全不透明，顶栏不继承。外层 Dock 裁剪时，`LyricsOverlayService` 只按可见高度比例更新 mask 的底部终点，完整歌词布局高度不变；该能力不增加定时器、逐帧脚本、动态模糊或额外歌词状态，性能验证以“无持续重绘、帧耗时无明确回退”为不变量。
16. 桌面歌词换句由 `lyrics_overlay.html` 一次性提交最终活动行、真实 `42px / 58px` 字号及最终模糊 / 阴影状态，再用 `220ms` FLIP 过渡歌词容器与受影响行的 `transform` / `opacity`；只对原文做逆向缩放，翻译保持独立真实字号。`font-size`、`filter`、`text-shadow`、颜色和 alpha mask 不参与逐帧插值；跳播、触摸、偏好、尺寸、主题、表面或翻译状态变化必须取消唯一临时动画 owner 并清除内联样式。
17. 顶栏与壁纸字号分别持久化；升级时只把旧单一字号作为两项尚未存在时的初始值。壁纸模糊默认开启、全句阴影默认关闭、排版默认标准、焦点默认中间；阴影关闭时所有歌词均无阴影，开启时所有歌词均有阴影。“顶部”内部目标为可视高度约 `15%`，位于固定渐隐带下方，不把当前句放入边缘透明区。
18. 人工查找由 `LyricsOverlayService` 绑定搜索开始时的当前播放身份，LRCLIB / QQ / 网易云并行返回每来源最多 `8` 条、合计最多 `24` 条候选。人工候选只排序、不复用自动准入淘汰；正文只在点选后读取，非同步正文拒绝写入。切歌、搜索代际变化、服务重建或用户再次搜索都会取消旧任务和可断开连接，旧回调不得覆盖新状态。
19. 设置状态通过包内显式广播返回，正文不离开服务 / 缓存主链。人工选择成功后写入当前播放身份的人工覆盖并让唯一 WebView 重新请求；恢复自动匹配只删除该人工覆盖。删除当前缓存清除当前身份的自动与人工记录；总容量达到 `128 MiB` 时由 `LyricsCache` 自动淘汰，无全量删除动作、广播或数据库 API。

### 4.1 商业权益状态流

1. `LyricsOverlayService` 仍先履行 Android 前台服务时限。每个新的服务生命周期同步读取一次 `CommercialAccessGate` 并异步发起一次轻量云端复核；即使系统授权缺失而即将进入授权恢复态，云端请求仍由进程级单飞任务继续完成并更新本地许可证。系统授权仍是歌词资源创建的第一道门禁，只有系统结果为 `RUNNING` 且本地商业结果为 `Allowed`，才调用 `ensureLyricsRuntimeResources()`。
2. 每个新的设置页实例继续执行完整权益查询。完整查询与服务轻量复核共享 `SingleFlightCommercialAccessRefresh` 的同一核心权益请求；并发等待方只共享当次结果，不缓存到下一次启动。设置页在核心权益结果后才读取待支付会话和活动报价，服务启动不访问活动或报价接口。
3. 本地有效许可证使歌词立即运行，云端复核不阻塞启动；网络、限流、超时、服务端异常或其它非权威失败只重新读取并尊重本地门禁。若本地无效，服务保持前台契约但不创建歌词 owner，等待当次复核；云端返回并持久化新的签名试用或 Pro 后恢复一套资源，复核失败则进入 `COMMERCIAL_RECOVERY`。`CommercialRuntimeAccessGuard` 只保存统一门禁已返回的单个 `Allowed?`，按 `expiresAtEpochMs` 安排一次到期回调，并在屏幕重新点亮、系统时间变化、每次创建表面或下发播放快照前复核时间边界，防止休眠或改时钟后旧许可复显；新许可证替换旧回调，到点后重新读取同一 `CommercialAccessGate`，不得从 UI 权益状态或设置动作旁路放行。
4. 商业拒绝进入独立 `COMMERCIAL_RECOVERY`：关闭并清空已经存在的歌词仓库、协调器、缓存、协程、MediaSession、WebView、窗口和车机监听，结束前台服务并留下进入“权益”分类的恢复通知；`PREF_AUTO_START` 保持原值。重新获准后才从 `ensureLyricsRuntimeResources()` 重建，不预留空转 owner。
5. 云端明确返回 `entitlement_revoked` 时，许可证仓库先写入加密撤销标记并使旧 Pro 许可证 fail closed；同一核心查询立即用既有 `startTrial` 合同请求原试用。只有新签名试用完成验签、许可证写入、可信时间写入和撤销标记删除后，查询才可原子收敛为 `Ready(Trial)`；试用过期收敛为 `Expired`，网络、验签或持久化失败继续返回原撤销结果。最终撤销时设置页 Controller 先发送专用 `REVOKED` 再渲染错误，启动复核直接进入 `COMMERCIAL_RECOVERY`；有效试用不得依赖第二个设置页或服务生命周期恢复，也不得在后续启动中与撤销状态交替。只有首次无本地权益且尚未创建任何歌词资源时，才允许在 denied 状态等待当次云端签发；已有仓库、监听或 Overlay 时一旦最终本地门禁 denied，必须先退出。
6. 领域页固定映射为：`Hidden / Paid -> ENTITLEMENT`，`Details / CreatingPayment / Expired / Error -> ORDER`，`AwaitingPayment -> QR`。广告横幅动作只派发 `EntitlementPageRequested`，不会派发 `CheckoutRequested`。
7. 试用、过期、PRO、首次查询和查询错误彼此区分。已稳定的 PRO 在后台刷新期间保持 PRO，不重新显示广告；最终非 PRO 结果才替换。PRO 生效后整个广告容器为 `GONE`，不存在高度占位。
8. `ProductQuote` 的 `quoteId`、原价、比例、折扣、计算金额、最终金额、最低支付标记、支付方式和有效期全部来自 API。状态机只选择和传递这些字段；输入未应用时不修改旧报价，客户端不做乘法、舍入或成交价推导。
9. 当前公开活动先经 `campaigns/current` 读取，再用返回码创建短期报价。无效 / 过期 / 不可用码仍接收原价报价；`quote_changed` 必须展示 `latestQuote` 并等待第二次确认；`already_owned` 直接保存许可证并进入 PRO。
10. 支付会话将 poll token 与二维码会话加密持久化，Activity 重建后可恢复。Controller 按服务端 `pollAfterSeconds` 自动轮询；网络或限流只在二维码页显示暂时状态并继续，支付成功后先保存 `deviceToken` 与已验签许可证再开放 PRO。
11. Debug fixture 在原始 HTTP / JSON 边界模拟全部八个接口，并验证设备签名与轮询原文；默认报价为 staging 小额边界。Debug 专属 Activity extras 不出现在正式页面，Release 不携带 fixture 金额、活动码、二维码域名、签名键或成功响应。
12. API 基址只由构建变体装配：Debug 默认 `fixture`；显式 `staging` 固定使用 `https://api-staging.9studio.fun` 且必须同时注入 staging 公钥与 `keyId`；Release 的 production 基址、公钥与 `keyId` 必须显式注入。本地构建不会因存在网络类而自动访问任一远端环境。

### 4.2 设备身份与许可证不变量

1. 初始设备签名键为 P-256 AndroidKeyStore 别名 `03lyrics_device_key_v1`；恢复换钥使用持久化的待确认别名。公开信息只导出 SPKI、公钥 SHA-256、签名证书 SHA-256 和设备指纹；指纹原文固定为 `ANDROID_ID + NUL + packageName + NUL + signingCertSha256`。
2. challenge 的 `signatureBase64` 固定签 Base64 解码后的 32 字节原文，不增加帧头。轮询固定签 UTF-8 文本 `purchaseId + "\n" + pollToken + "\n" + timestampSeconds + "\n" + nonceBase64Url`；nonce 至少 16 字节并且每次重建。设备私钥不导出，Key Attestation 仍只作非阻断能力探测。
3. 许可证先对 `payloadBase64` 解码出的原始 JSON 字节执行 `SHA256withECDSA`，通过后才解析并核对 envelope / payload / 配置三方 `keyId`、版本 `1`、产品、当前公钥摘要、设备密钥版本、签发 / 到期 / 离线宽限 / 试用截止的顺序和当前时间。PRO 在 `expiresAt..offlineGraceUntil` 仍可离线使用；试用没有额外离线宽限。
4. 许可证、权益撤销标记、device token、poll token、未完成支付会话、首次打开时钟、许可证可信时间、设备密钥版本、活动密钥别名和待确认恢复别名使用独立 AES-GCM AndroidKeyStore 别名 `03lyrics_commercial_storage_key_v1` 加密，按记录名作为 AAD 写入 `noBackupFilesDir`。撤销标记优先于任何仍存留的许可证；新的有效签名许可证完成持久化后才允许重新开放门禁，云端明确确认原试用已过期时可在删除旧许可证后把标记收敛为无许可证的过期态。
5. 首次试用必须联网取得云端签名许可证；本地首次打开时间只作为请求输入，不能授权歌词资源。重复请求、进程重建、重装或同指纹换钥均以云端原始试用起止为准，客户端只接受签名 `trialEndsAt`。
6. 恢复时，已有已知云端 key 版本则生成待确认新钥并用旧钥对同一 challenge 附签；旧钥 / 本地版本不存在时用当前新钥走同指纹恢复。启动权益查询只有在云端明确返回 `device_key_mismatch` 时自动调用现有恢复主链一次；`device_fingerprint_mismatch` 与其它安全失败不进入恢复，自动恢复结果也不得递归。待确认别名在网络响应丢失后保留并复用，成功后才切换活动别名、保存新版本并清理旧钥。

## 5. 已验证几何不变量

所有坐标以 `1920 x 1080` 设计空间表达，运行时按真实屏幕等比换算。

1. 桌面歌词区域：`x = 660..1890`，`y = 90..900`。
2. 顶栏歌词基线：右边界 `x = 881`；没有动态图标时左边界 `x = 321`，可用宽度 `560 px`。
3. 已确认动态图标包括行人提醒、无线充电、SD 卡/DVR、USB 存储和守护模式。
4. 每个确认可见图标占用 `75 px`（`42 px` 图标 + `33 px` 安全间距）；未知状态不占用宽度。
5. 顶栏歌词最小可用宽度为 `180 px`；不足时隐藏该表面，不覆盖不确定区域。
6. 表面模式只由启动器状态、系统窗口占用、外部桌面表面租约和用户显示策略决定；图标可见性只影响顶栏几何，不改变表面模式。
7. 目标车机的 `Settings.Secure` 键 `com.mengbo.launcher3.settings.secure.window_mode` 的已确认多值语义为：`0` 无窗口、`1` 仅 ADAS 左侧卡片、`2` 标准浮窗、`3` 同时存在 ADAS 卡片和标准浮窗。仅 `0/1` 允许桌面歌词，`2/3` 退回顶栏；其它值或读取失败按未知占用保守处理。
8. `global_setting_ac_page_status` 的已确认语义为：`1` 展开、`3` 开始展开或过渡、`2` 完全收起；展开和过渡期间始终占用，读取失败同样 fail closed，只有完全收起才恢复歌词。

## 6. 歌词匹配与网络不变量

1. 缓存未命中时并发启动 LRCLIB 精确单条，以及 QQ 音乐、网易云各自搜索计划的第一项；结果按实际完成顺序进入本地核验，不设置等待所有首轮来源的同步屏障。目录搜索计划每个来源最多三项，固定按“标题 + 原始歌手、标题 + 专辑核心、标题 + 歌手完整主体、仅标题”生成、去重并截断；前一项没有可获取正文的合格候选时，该来源立即推进下一项。任一结果必须通过录音核验且包含同步歌词，才能进入最终选择。
2. 正式歌词匹配只接受已知时长（至少 `1000 ms`），候选与当前播放时长差不得超过 `2000 ms`。现场、混音、重制、伴奏、翻唱、语言版等录音版本并入标题证据：双方版本类别相同或都未标注为 `EXACT`，仅一侧标注为 `NEAR`，双方都明确标注且类别不同为 `DIFFERENT`。只有明确版本冲突才拒绝；同类版本的地点、年份等附加描述可继续比较。时长和明确版本冲突是录音边界，不能被其它名称证据或来源数量抵消。
3. 标题、歌手和专辑统一形成 `EXACT / NEAR / UNKNOWN / DIFFERENT` 四级证据，并保留归一相等、发行核心、连续主体、编辑相似、跨文字未知、版本省略或明确冲突等具体原因。时长和已确认标题是硬门槛；标题中的明确版本冲突归入 `DIFFERENT`，歌手为 `DIFFERENT` 时也一律拒绝，二者都不能被专辑相等或来源数量抵消。通过硬门槛后，候选还必须满足“歌手已确认、专辑已确认、或两个独立来源共同补充 `UNKNOWN`”之一。标题 `4 / 3 / 0 / -5`、歌手 `3 / 2 / 0 / -2`、专辑 `3 / 2 / 0 / -1` 和独立来源 `+2` 只用于已合格候选排序，不再充当准入阈值；同一来源重复结果不算独立证明。
4. 近似文本先做 Unicode、大小写、标点、空格和重音归一；标题、歌手、专辑的编辑相似阈值分别为 `85% / 90% / 80%`，且至少 `8` 个归一化字符才启用编辑距离。标题主体与歌手展示名在压平前按空格、点、下划线、连字符及文字体系切换保留有序分段：一方完整分段序列连续包含于另一方，或双方共享占主体的连续分段且剩余部分只是跨文字展示时记为近似。格式符本身不进入全文比较，分隔后的多段可以组合成连续主体，但不得改写为合作歌手；没有明确分段的同文字任意字符子串和非连续片段拼接不得据此入选。专辑核心文本覆盖达到 `70%` 可视为近似；末尾由破折号、冒号或括号独立分隔的 `Single / EP` 属于发行类型，剥离后核心专辑名完全相等可记为近似，无独立分隔的普通专辑词不得剥离。明确双语括号标题可为跨文字标题提供等价桥接。跨文字体系且没有桥接时记为 `UNKNOWN`，只表示等待更多标题证据：不得单独入选、不得参与来源共识，也不能只凭歌手、专辑和时长补足。不维护人物、歌手或歌曲特判表。
5. `feat.`、`ft.`、`featuring`、`with` 属于合作歌手信息，不属于录音版本；允许该信息在标题括号与歌手栏之间移动，也允许来源省略已明确标注的合作歌手。普通标题括号附注不作硬门槛；合格候选先按版本证据 `EXACT -> NEAR`，再按排序分、括号信息“完全一致、相似或省略、完全不一致”、独立来源数、时长差、来源和来源曲目 ID 排序，使已有明确同版候选优先于单侧省略版本的候选，但不阻断后者作为单来源结果。
6. LRCLIB 精确请求使用标题主体、有效歌手（含标题中的合作歌手）、剥离独立 `Single / EP` 发行后缀后的专辑核心文本和毫秒时长换算值，只返回单条结果。精确结果单独合格时立即返回，单独不足时保留到后续已完成目录候选共同核验。QQ / 网易云某项目录结果没有合格候选时立即推进本来源下一项；有合格候选时先读取正文，正文为空后继续本来源剩余计划。最多并行两条不同来源正文通道，首个有效同步歌词立即返回；LRCLIB 精确请求与所有目录计划均已完成且没有正文在途，或到达 `1800ms` 首轮截止仍未解决时，才启动 LRCLIB 模糊列表。所有路径共享原总截止和正文通道。
7. 精确与目录首轮截止 `1800 ms`，单次查询总截止 `3800 ms`；连接超时 `1500 ms`，读取超时 `2200 ms`，封面总截止 `3000 ms`，单响应最大 `2 MiB`。瞬时失败只在当前请求仍为最新时等待 `1000ms` 并完整重试一次；代码中不得加入其它 `sleep` 或人为等待。远程封面只在最终歌词结果未携带封面时补查，不与歌词正文争抢首轮通道。
8. 每次在线入选必须携带当前匹配策略版本及最多两条支持候选；组合证据只复用已返回目录，不增加证明请求。占位歌手、空内容、`null`、`[object Object]` 和普通无时间轴歌词不得进入顶栏同步歌词主链；WebView 不得绕过原生解析主链直接请求歌词源。解析日志记录查询种类、候选数量、正文是否为空、耗时，以及最多前三条候选的拒绝原因、证据等级和独立来源数；不记录歌词正文或完整播放历史。
9. QQ 只读取歌词响应中的 `trans`，网易云只读取同一响应中的 `tlyric.lyric`；翻译必须自身包含同步时间轴才可进入结果。翻译不改变 LRCLIB 精确短路、候选排序、请求数量或截止时间，也不替换已经确认的原歌词来源。
10. 呈现层以归一化毫秒时间戳配对原文与翻译，最大差值为 `120ms`；每个原文和翻译行最多使用一次，缺行不得按数组序号顺延，翻译时间不得改变原文的活动行判定。
11. 人工目录搜索总截止与正文加载截止均为 `3800ms`；目录阶段不得预取歌词正文。人工候选可以与当前元数据不满足自动准入，但必须具有来源和来源 ID；用户点选后的正文仍必须通过同步时间轴分类，才能进入人工缓存。

## 7. 缓存不变量

1. 自动与人工歌词缓存共享 `128 MiB` 逻辑上限，触发清理后目标为上限的 `90%`；优先按既有淘汰分清理自动缓存，仍超限时再按更新时间清理旧人工覆盖。自动缓存每批最多淘汰 `256` 条，人工覆盖最多保留 `128` 首。
2. 缓存使用 SHA-256 的标准化“歌曲 + 歌手 + 专辑 + 候选录音时长（秒级）”身份作为 key；读取时只探测当前播放时长正负 `2` 秒内的 key，并用载荷中的匹配策略版本和最多两条支持候选重放完整准入。在线依赖双来源或双语标题桥接的结果不得在缓存读取时被降成单来源判断；匹配语义变化时递增策略版本，旧证明按未命中处理并在正常网络命中后替换，不为兼容旧结论绕过当前选择器。
3. `30` 天后允许刷新歌词；访问频率最多累计 `30` 次，每次为淘汰分增加 `7` 天权重。
4. 读取优先级固定为“人工覆盖 > 自动缓存 > 在线自动匹配”。人工覆盖按当前播放身份写入独立表，不伪造自动入选证明、不受 `30` 天刷新影响；删除人工覆盖后原自动缓存继续有效。缓存策略与空间阈值只由 `LyricsCache` / `LyricsCachePolicy` 管理，服务层不得复制。
5. 匹配策略切换为证明准入时数据库升级到版本 `3` 并清空旧无证明缓存，避免旧分值结果被直接复用；歌词会按正常播放重新建立。版本 `4` 只新增人工覆盖表，`3 -> 4` 必须保留已有自动缓存；更旧版本仍先执行原有自动缓存身份迁移。翻译继续作为可选字段与自动歌词、入选证明存入同一 JSON 载荷；有效证明载荷若缺少翻译字段，仍先返回原文并只触发一次后台刷新。

## 8. 绝对边界

1. 不把 `03桌面` 的应用抽屉、安装、卸载、快捷控制或右侧手势面板放进本项目。
2. 不写车辆状态或厂商窗口状态，不连接 CAN，不调用未经独立验证的车厂私有控制接口。

5. 包名、签名和升级身份的变更必须先有独立迁移方案和实机升级验证。
6. 深浅主题适配不依赖厂商私有主题键、截图、亮度推断或轮询；仅设置页可只读监听已实机验证的公开主题色键作为强调色输入，且不得形成第二套深浅主题状态机、不得写回系统设置。
7. 标准浮窗互斥的启动编排属于实际发起应用启动的一方；本项目只在 `MainActivity` 清单元数据中声明标准浮窗身份。跨应用桌面区域冲突只接收版本化、无业务 Binder 的通用绑定租约，不识别调用方包名，也不接入其它产品源码。

9. 车厂私有 `MBSwitch` 仅作资源取证来源；正式 APK 使用项目自有控件承载同一几何、主题色和 Android 开关无障碍语义，不链接车厂私有类或资源 ID。
