# 03T 诊断 APK 与 03投屏能力取证

## 目标

提供一个独立 `diagnostic` 构建类型的诊断 APK，配合一次性 ADB 脚本，确定 03T 上的媒体契约、03投屏能力基座和启动闪退层级。诊断 APK 的包名为 `com.ninepointnine.desktoplyrics.diagnostic`，不替换正式或普通 Debug `03歌词`，不进入 Release。

## 证据边界

诊断 APK 只读取公开 Android 能力和当前应用可访问的公开媒体契约：设备 Build、网络接口、Wi-Fi 多播锁、mDNS/SSDP 探测、已安装 03投屏包的 PackageManager 信息、MediaCodec 静态能力、Automotive 公开只读属性、所有活动 MediaSession，以及公开导出的 Framework / AndroidX MediaBrowser 服务。

诊断 APK 不加载 03投屏 native 库，不启动 AirPlay/DLNA，不绑定 `7000/tcp`、`8200/tcp` 或 `1900/udp`，不读取其它应用的 logcat 和 tombstone，不上传媒体正文。

主机侧 `scripts/collect-desktopcast-diagnostics.mjs` 负责一次性读取 ADB 证据：安装包静态内容、Launcher 解析、启动后 Activity/Service/PID、`exit-info`、窗口、端口、连接、Wi-Fi、MediaCodec、media extractor、媒体会话、Automotive service 和筛选后的 logcat，并自动拉取诊断 APK 的 JSON/TXT 报告。默认不清空既有 logcat；必须显式传入 `--clear-logcat` 才清理。

## 03投屏能力基座

当前独立 `03投屏` 的关键能力为：

1. `arm64-v8a` native 运行时，包含 `libairplay_native.so`、`libc++_shared.so`、`libcrypto.so`、`liboboe.so`。
2. `INTERNET`、网络状态、Wi-Fi、Wi-Fi 多播锁和 `WAKE_LOCK`。
3. AirPlay native 主监听 `7000/tcp`，DLNA HTTP `8200/tcp`，DLNA SSDP `239.255.255.250:1900/udp`，mDNS/DNS-SD 依赖系统多播能力。
4. Android `MediaCodec` 的 AVC/HEVC Surface 解码；真实配置和真实 RTP 数据仍需发送端连接才能最终确认。
5. `CastService`、标准浮窗 `MainActivity`、全屏 `FullscreenActivity` 和全屏独占租约。
6. 可选 `android.car` 和 `CAR_POWERTRAIN` 只读档位访问。

## 闪退判定

| 证据 | 判定 |
|---|---|
| `arm64-v8a` 或 native 库缺失 | APK/ABI 打包问题 |
| `UnsatisfiedLinkError` | native 库、依赖或 ABI 不匹配 |
| Activity Java `FATAL EXCEPTION` | Activity、资源、主题或类初始化 |
| Service 创建后立即死亡 | Service 生命周期或 lazy 依赖构造 |
| `SIGSEGV` / `SIGABRT` 且涉及 `airplay_native` | JNI/native/UxPlay 生命周期或 ABI |
| 7000 / 8200 bind 失败 | AirPlay 或 DLNA 监听端口冲突/绑定失败 |
| mDNS/SSDP 无响应 | 网络接口、多播锁或广播基座 |
| 真实连接后 MediaCodec configure/start 失败 | codec profile、Surface 或厂商实现 |
| 全屏切换后崩溃 | Activity handoff、Surface 或全屏租约 |

## 使用顺序

1. 安装独立诊断 APK 后，在 ADB 助手中执行 `cmd notification allow_listener com.ninepointnine.desktoplyrics.diagnostic/com.ninepointnine.desktoplyrics.MediaListenerService 0`，再执行 `settings get secure enabled_notification_listeners`；输出必须同时保留原有组件，并包含诊断组件。该命令通过系统通知服务幂等授权，不直接覆盖现有监听名单。
2. 在车机播放待测媒体应用歌曲（优先车内网易云），打开独立诊断 APK；页面必须显示“媒体读取授权：已开启”，再执行完整诊断。报告会记录所有活动媒体包、原始字段、归一字段、公开 Browser 服务清单以及有限连接探测结果。APK 将 JSON/TXT 写入车机应用专属目录，主机侧 ADB 脚本会自动拉取报告，不依赖系统分享面板。
3. 再执行 30 秒媒体动态采样，期间暂停、恢复和切歌。
4. 复现正式版 03投屏闪退时，在电脑端运行 `node scripts/collect-desktopcast-diagnostics.mjs`；若必须隔离本轮日志，再显式追加 `--clear-logcat`。
5. 若正式版 03投屏能够稳定启动，再由真实 AirPlay 或 DLNA 发送端连接一次，结合 MediaCodec、Surface 和协议日志判断运行兼容性。

## 不能由静态诊断证明的事项

静态 APK、权限、端口和 codec 枚举不能证明真实 AirPlay 加密握手、RTP、SPS/PPS、DLNA 媒体格式、Surface BufferQueue 交接和全屏任务切换全部成功。这些必须保留一次真实发送端运行证据。
