# 03lyrics 验证矩阵

## 1. 环境入口

1. 本机环境检查：`node scripts/check-local-environment.mjs`
2. 追加车机连接检查：`node scripts/check-local-environment.mjs --device`
3. 文档底座检查：`node scripts/check-project-docs.mjs`
4. Skill 结构检查：`node scripts/check-skills.mjs`
5. Git 文本检查：`git diff --check`
6. 自动覆盖安装与基础 smoke：`node scripts/install-and-smoke.mjs`

实际 JDK、Android SDK 和 ADB 路径从被忽略的 `.codex/local-context.properties` 读取，不写死在命令或提交文档中。

## 2. Android 自动验证

| 变更类型 | 必须执行 |
|---|---|
| 只读查询 | 不默认跑构建 |
| 文档、规则、Skill、脚本 | 文档检查、Skill 检查、`git diff --check` |
| Kotlin 纯规则或缓存策略 | 直接相关单测；没有对应单测时执行受影响模块编译 |
| Android 配置、普通资源 | `assembleDebug` + 自动覆盖安装与基础 smoke |
| Android 权限、安全、签名或数据迁移 | 相关单测、`lintDebug assembleDebug`，并按风险补验证 |
| 歌词匹配或外部源解析 | `DirectLyricsRepositoryTest` + 全量 JVM 单测；必要时受控网络 smoke |
| 车机状态和顶栏几何 | `IcarDisplayStateMonitorTest` + 自动覆盖安装 + 最简状态切换 smoke；完整组合由用户主测 |
| 缓存 | `LyricsCachePolicyTest`；涉及 SQLite 行为时补并运行 `LyricsCacheInstrumentationTest` |
| 悬浮层 HTML/CSS/JS | `assembleDebug` + 自动覆盖安装 + 最简截图/日志 smoke；完整交互由用户主测 |
| 启动、停止、开机恢复 | `assembleDebug` + 自动覆盖安装 + 最简启动 smoke；重启闭环由用户主测或另行授权 |

在当前本机配置下，需要完整验证时由以下逻辑步骤组成；普通敏捷施工不默认执行完整集：

```text
从 .codex/local-context.properties 读取 JDK17_HOME
以该 JDK 运行 ./gradlew testDebugUnitTest lintDebug assembleDebug
```

## 3. 单元测试覆盖

1. `DirectLyricsRepositoryTest`：歌词类型、标题/歌手匹配、跨来源选择、竞争版本静默。
2. `IcarDisplayStateMonitorTest`：启动器表面策略、五类动态图标、保守未知态和顶栏几何。
3. `LyricsCachePolicyTest`：缓存预算、清理目标、频率上限、淘汰偏好和时长 key 查找窗口。
4. `LyricsCacheInstrumentationTest`：独立测试数据库中的旧缓存升级失效和读取前时长复核。

## 4. 目标车机运行级 smoke

AI 在每次实现完成后先自动执行保留数据覆盖安装与本次改动的最简 smoke，通过后交给用户执行完整场景。完整 smoke 包含：

1. 权限入口：通知使用权、悬浮窗权限和前台服务能正常启用。
2. 播放闭环：播放、暂停、拖动进度、切歌后歌词与时间线同步。
3. 表面切换：壁纸、地图、车辆设置、设置页打开/关闭时表面和可见性正确。
4. 动态图标：无线充电、存储和守护模式等已知图标变化后，歌词左边界实时更新且不重叠。
5. 生命周期：主动停止不恢复；保持启用时应用升级和车机重启后恢复。
6. 安全界面：倒车影像和车辆警告出现时，歌词层不覆盖其高优先级界面。
7. 主题切换：歌词服务运行且歌曲正在播放时切换深色/浅色，设置页和当前歌词表面同步换色，歌词行、播放进度和悬浮表面保持连续。

## 5. 交付记录

1. 必须逐项写明实际执行命令、覆盖闭环和结果。
2. 未执行实机项必须说明客观阻断，如未授权安装、设备离线或车辆场景不可用。
3. 剩余人工确认必须压缩为具体动作，不能要求用户“整体回归”。
4. 自动安装或最简 smoke 未通过时不得进入用户主测阶段；修复后必须重新构建、安装并 smoke。
5. 用户主测有问题则继续迭代；用户确认无问题后仍需等待明确提交指令，不把测试反馈自动解释为 Git 授权。
