# 03lyrics 验证矩阵

## 1. 环境入口

1. 本机环境检查：`node scripts/check-local-environment.mjs`
2. 追加车机连接检查：`node scripts/check-local-environment.mjs --device`
3. 文档底座检查：`node scripts/check-project-docs.mjs`
4. Skill 结构检查：`node scripts/check-skills.mjs`
5. Git 文本检查：`git diff --check`
6. 自动覆盖安装与基础 smoke：`node scripts/install-and-smoke.mjs`
7. 商业安全事务测试（非默认，仅一次性模拟器或独立测试设备）：`node scripts/run-commercial-security-instrumentation.mjs`
8. staging APK 在安装前必须对实际产物执行签名校验：证书 SHA-256 为 `64` 位十六进制、与仓库外 staging keystore 证书及构建注入的预期 signer 一致、APK Signature Scheme v2 有效且只有一个 signer；同时扫描 APK，确认未包含 Cloud 许可证私钥、pepper、折扣 AES 密钥、签名口令或其它服务端秘密。

实际 JDK、Android SDK 和 ADB 路径从被忽略的 `.codex/local-context.properties` 读取，不写死在命令或提交文档中。

商业 instrumentation 不属于日常车机收尾。普通商业权益改动默认只运行相关 JVM 测试、必要的 lint / 构建、保留数据安装与最简运行 smoke；只有修改直接触及 instrumentation 隔离或 AndroidKeyStore 真机行为且较低层级无法覆盖时，才升级执行。一次性模拟器可以在唯一连接且允许清状态时定向运行；物理测试必须配置与 `VEHICLE_ADB_SERIAL` 分离的 `COMMERCIAL_TEST_ADB_SERIAL`，并由 `COMMERCIAL_TEST_DEVICE_ROLE=dedicated-test-device` 标记为独立测试设备。脚本在这些配置缺失时会在任何设备操作前退出。用户日常车机默认禁止；例外必须由用户当次明确授权，将角色设为 `persistent-user-vehicle`，并显式传入 `--user-approved-persistent-vehicle`。允许执行后仍需统一使用事务脚本完成签名核对、隔离测试、专用清场、辅助包卸载、正式记录哈希比对和同一目标设备的恢复 smoke；不得手工拆散步骤、额外 `am force-stop` 或自动重启设备。

## 3. 单元测试覆盖

1. `LyricsSearchPlannerTest` 覆盖每来源查询顺序、去重、三项上限、专辑核心和歌手完整主体；`PublicLyricsSourcesTest` 用 QQ / 网易云真实字段结构验证显式查询编码、目录解析、同步正文和同源翻译。`DirectLyricsRepositoryTest` 覆盖歌词类型、标题/歌手/专辑带原因的四级证据、显式准入与排序分分离、明确不同歌手硬拒绝、轻微拼写、双语标题桥接、有序连续主体及反例、发行类型、跨文字未知态、证明重放、单侧版本省略和明确版本冲突；`DirectLyricsRepositoryOrchestrationTest` 另覆盖人工目录结果不走自动准入淘汰、每来源 `8` / 总计 `24` 上限，以及搜索阶段不下载正文、只加载点选同步歌词。`LyricsResolutionCoordinatorTest` 覆盖最新请求取消、瞬时失败只重试一次和完成无匹配不重试。`DirectLyricsRepositoryLiveNetworkTest` 只在显式环境开关下运行完整生产仓库，验证《千年泪》跨发行目录结果和《Twinkle》本地化组合名可取得正确同步歌词，不绑定第三方可变曲目 ID；`DirectLyricsRepositoryNetworkInstrumentationTest` 用于目标车机上的同类网络路径，以及其它本地化目录证据、单侧现场版标记和近时长错误候选反例。

## 4. 目标车机运行级 smoke

本节只承接正式应用的最小运行检查，不包含商业 instrumentation、androidTest APK 安装、无障碍暂停、强制结束应用或设备重启。前述动作均不得由普通施工或“高风险改动”自动推导。

AI 在每次实现完成后先自动执行保留数据覆盖安装与本次改动的最简 smoke，通过后交给用户执行完整场景。完整 smoke 包含：

1. 授权前置：受控部署已提供通知使用权、悬浮窗权限和“歌词窗口避让”无障碍服务，前台服务能正常启用；应用设置页不承担授权入口。安装流程必须从当前 APK 解析实际应用 ID，再与源码 namespace 组合 `IcarDockAccessibilityService` 组件并幂等追加到现有已启用无障碍服务列表；不得写死正式包覆盖 `.test` 身份，不得覆盖已有组件，也不得把特殊访问误写成 `pm grant`。
2. 播放闭环：播放时歌词与时间线同步；同一首可信歌词暂停后冻结并保持显示，恢复播放后从冻结位置继续；暂停时首次出现的新曲目不提前显示，切歌、停止和无会话会清除旧歌词。不含前置信息且以超长首句开头时，前奏可预览该句但必须保持起始位置，到达首句时间点后才横向滚动，回退前奏后再次复位。默认开启翻译时，同源翻译歌曲在桌面作为原文附属小字显示，顶栏一行显示当前原文与翻译、两行再保留下一句原文；无翻译歌曲只显示原文，关闭开关立即恢复原布局。
3. 表面切换：壁纸、地图、车辆设置、行车记录仪、应用中心和本项目设置页打开/关闭时表面与可见性正确；任一标准浮窗打开时桌面歌词退回顶栏，顶栏歌词不消失。顶栏与桌面往返必须表现为旧表面 `120ms` 淡出、不可见时换位和换布局、新表面 `160ms` 淡入；不得出现双表面、可见跳位、闪帧或残影，快速往返后最终表面必须与最新车机状态一致。壁纸歌词上下各 `64px` 内渐隐到透明，中部和壁纸本身不得变暗或变色；顶栏计算样式必须保持无 mask。
4. 动态图标：无线充电、存储和守护模式等已知图标变化后，歌词左边界实时更新且不重叠。
5. 生命周期：主动停止不恢复；保持启用时应用升级和车机重启后恢复。
6. 安全界面：倒车影像和车辆警告出现时，歌词层不覆盖其高优先级界面。
7. 主题切换：歌词服务运行且歌曲正在播放时切换深色/浅色，设置页和当前歌词表面同步换色，歌词行、播放进度和悬浮表面保持连续；该深浅主题闭环已经用户主测通过。粉色主题必须读取公开键 `33`，在导航、分段、开关、折扣标签和商业动作上保持一致；其它主题键不得以纯规则单测代替实机通过结论。
8. 标准浮窗：打开时整个窗口从底部向上进入，系统返回或任务退后台时整个窗口向下退出；底层页面静止，结束后窗口仍为 `1230 x 810px`，无尺寸跳变、残影或背景分层错位。
9. 窗口占用信号：桌面读取值为 `0`，左侧 ADAS / 充电卡片单独展开为 `1`，两者均允许桌面歌词；上述标准浮窗前台为 `2`，左侧卡片与标准浮窗同时存在为 `3`，两者均退回顶栏。其它值或读取失败时歌词保守留在顶栏；关闭冲突窗口后按当前启动器状态恢复。
10. 设置页：左栏“歌词设置 / 服务状态 / 歌词缓存 / 歌词查找 / 权益中心”使用固定图标列与四字标签对齐，底部固定“关于”入口，切换不启动新 Activity。未保存过对应偏好时，壁纸歌词阴影、开机自启动和歌词位置“右侧”均显示为开启或选中；顶栏一行字号和两行第一 / 第二行字号各五档且互不覆盖，切换行数只改变可见的字号分组；壁纸启用、模糊、阴影、排版、焦点和“歌词位置：左侧 / 右侧”即时生效且不改变顶栏，阴影关闭时所有歌词均无阴影、开启时所有歌词均有阴影，顶部焦点在可视高度约 `15%` 且不进入 `64px` 渐隐区；所有开关均显示简介。服务页运行开关反映当前服务，重启保持全宽一次性动作且不显示授权入口；授权不足时使用设置窗口内的普通信息弹窗，`知道了` 和系统返回都只关闭弹窗。缓存页能区分无歌曲、未缓存、自动与人工状态，并显示按当前平均大小估算的剩余可缓存歌曲数；删除当前歌曲缓存是唯一删除动作。查找页三个输入框与搜索按钮同一行，搜索图标与文字共同水平居中，结果显示来源 / 歌曲 / 歌手 / 专辑 / 时长，点选后立即替换并在重进歌曲时保持，恢复自动后回到自动缓存或在线匹配。关于页先显示版本号信息项（左侧“版本号”、右侧 `BuildConfig.VERSION_NAME` 对应的当前构建实际版本），下方显示“用户协议”标题和二维码，二维码由构建环境决定地址且离线可见。人工搜索期间不得观察到批量正文请求。
11. 手动重启：点击后同一 `LyricsOverlayService` 实例完成资源重建，`PREF_AUTO_START` 与显示偏好不变；仅存在一个前台服务、一个 `APPLICATION_OVERLAY` 窗口和一套 MediaSession/音频/AVRCP/车机监听，播放状态继续更新且无致命日志。
12. 表面租约：覆盖安装后，`cmd package query-services --brief -a com.tcrrry.icar.surface.action.ACQUIRE_OCCUPANCY_LEASE` 与 `cmd package query-services --brief -a com.tcrrry.icar.surface.action.ACQUIRE_FULL_DISPLAY_OCCUPANCY_LEASE` 必须分别发现本应用的两个 Lease Service；`03桌面` 右侧面板开始展开即退回顶栏，展开和收起动画全程保持顶栏，完全收回后重新按第 9 条窗口值与用户偏好计算；合作投屏应用进入全屏时歌词必须隐藏，退出全屏后按最新窗口状态恢复。
13. 授权恢复退化：保留 `PREF_AUTO_START=true`，临时撤销悬浮权限后从停止状态请求启动，至少观察 `10` 秒；必须记录启动来源、两项授权和 `outcome=recovery`，不存在 `RemoteServiceException`，`LyricsOverlayService` 结束且 `MediaListenerService` 保持系统绑定，并存在点击后进入现有设置页的恢复通知。恢复原授权并显式启动设置页后，必须记录 `outcome=running`、清除恢复通知，只存在一套服务、Overlay 和监听。测试结束恢复临时授权状态，不自动重启车机。
14. 商业综合卡与主题：试用态在四个非权益分类顶部显示同一中性大底框并避开系统拖动横条；左侧状态垂直居中，右侧把“现在购买 Pro”、立享折扣和价格对比作为一个整体，上行标题紧邻折扣，下行价格右缘与折扣右缘均为屏幕 `x = 1775px`，末端保留大箭头。折扣标签、箭头、主按钮和支付方式选中态与导航使用同一强调色。点击整卡进入权益主页后，卡片及其高度占位立即消失；PRO 后同样保持消失，左栏保留金黄 Pro 角标。新增页面不得改变既有综合卡和权益页几何。
15. 商业页面流：权益主页不出现 slogan。有可购买报价时顶部居中显示试用权益状态和剩余时间，顶部状态组必须为 `[1040,146]..[1814,234]`；无报价、确认中、无法确认或其它只有状态与底部动作的状态，主状态和恢复反馈必须位于页面顶部留白与底部动作组之间的可用区域中心，不按整页高度机械居中，并与底部按钮保持明确间距；底部只保留动作入口。有报价时底部购买组必须为 `[1040,723]..[1814,844]`，顶部 / 底部组距对应页面边缘均为 `56px`。中间营销组必须为 `[1247,393]..[1606,565]`，上行购买标题紧邻右侧折扣，下行双列原价 / 限时价与上行同宽且限时价右缘和折扣右缘一致；营销组在上下两组之间垂直居中，不显示方向箭头。PRO 完成组必须为 `[1040,408]..[1814,582]`，包含金色皇冠、居中主标题和永久权益说明，营销、支付与恢复入口全部隐藏。撤权主页必须显示“权益已撤销，需重新获取Pro”和唯一“获取Pro”主按钮，点击后先拉取最新报价再显示订单，报价失败仍留在可重试主页。点击后主页消失并显示订单详情，点击支付后订单详情消失并显示固定二维码；订单 / 二维码页的页面返回或系统返回只回权益主页，等待至少 `7s` 不得被晚到结果重新带回。轮询网络失败仍留在二维码页；Debug 标记成功后二维码消失、自动回到同一居中完成组并显示“支付成功 / 权益生效中 · 永久”。
16. 报价与订单：Debug 默认自动读取 fixture 当前活动并显示 `¥0.02 / 5折 / ¥0.01`，`minimumChargeApplied=false`；订单说明左对齐、结果右对齐，折扣码控件比例稳定，最终价格独立成行。正常态订单返回入口从 `y = 146px` 开始，“支付”必须为 `[1295,781]..[1559,844]`，上下外缘距页面均为 `56px`；微信 / 支付宝选择条随支付组共同定位于 `y = 689..740px`，不要求与权益页“前往支付”同位。任意无效码应用后显示“折扣码无效 / 无折扣 / ¥0.02”，仍可按原价创建微信或支付宝订单。`commercial_debug_payment=changed` 时展示最新原价报价并等待再次确认；`expired` 回订单页；`owned` 不生成重复订单。
17. 商业恢复：`commercial_debug_recovery=same` 使用 recover challenge 完成换钥并进入 PRO；`different` 明确显示设备不一致；`network` 保留原本地权益，不显示成未购买。未完成支付关闭并重开设置页后恢复二维码与自动轮询。
18. 商业门禁：Debug 试用时设置页启动后歌词服务、唯一 Overlay、MediaSession 和歌词请求资源正常；设置页与歌词服务必须通过同一 `CommercialEntitlementCoordinator` 消费共享权益快照，新建歌词服务时日志必须先出现一次 `Commercial startup revalidation started`，随后出现一次 `completed`，同一服务实例接收设置或显示命令不得重复发起。启动、服务新生命周期、用户重启和设置页打开均走一次 `license/check`；`active` 时本地许可证 bytes、`licenseId` 和时间不变且 `license/refresh` 请求为零。网络失败且本地凭证仍在签名窗口内时 Overlay 持续存在并记录待复核；切到 `revoked`、固定七天过期或无本地许可证的失败后，歌词仓库、协调器、缓存、协程、MediaSession、WebView、Overlay 和监听均释放，`PREF_AUTO_START` 保持为真。试用 24 小时租约到期时用当前设备密钥重新取得短租约，不轮换密钥；永久 PRO 无本地终点。真实退款时首次冷启动查询必须直接稳定为撤销 / 零 Overlay，不得先停用后依赖第二次设置页查询恢复；新许可证持久化失败期间继续保持零 Overlay。
19. Release 隔离与环境真值：Release APK 只构建不安装，解包后不得命中 `0.02 / 0.01 / 49.00 / 29.40 / icar 03 / debug-fixture / fixture.03lyrics.invalid / commercial_debug_ / DEBUG FIXTURE`。普通 Debug BuildConfig 必须默认为 `fixture`；真实退款、撤权、重新报价、订单与二维码验证必须显式构建并安装 staging Debug，安装前核对 `DEVICE_COMMERCE_ENVIRONMENT=staging`、测试 API 基址、`.test` 包名和长期 staging signer，不得用 fixture 冒充测试后台结果，也不得把 staging 包安装到 production 身份。
20. staging 签名兼容性：只读提取目标车机已安装 APK 的签名证书并与 staging 产物比较；证书不同时禁止覆盖安装，必须先说明卸载会清除的设置、歌词缓存、商业许可证 / 试用状态、设备密钥与系统特殊授权，等待用户在 Cloud 可联调后单独授权卸载。
21. 原车 SR、Dock 与空调：默认右侧壁纸歌词窗口为 `[660,90]..[1890,900]`；选择左侧后为镜像 `[30,90]..[1260,900]`。左侧模式下将 SR 滑出或收回，系统合并事件后 SR 把手首次产生至少 `8px` 横向变化时，歌词应立即开始 `250ms` 先快后慢位移，日志中的 SR 方向提示和 Overlay `x` 变化必须先于 `window_mode` 终值；不要求跟随手势进度。最后一次事件后 `320ms` 复核清除瞬时提示，此后窗口保持与 `window_mode` 终值一致且不反弹。左侧歌词原位时，左 Dock 展开到 `y=586` 应把窗口裁到约 `y=570`；SR 推开后改由中间 Dock 触发同样裁剪，左 Dock 不再影响；右侧位置始终只由右 Dock 裁剪。`global_setting_ac_page_status=1/3` 时唯一歌词 Overlay 保留但根视图不可见，值回到 `2` 后按实时 SR、Dock、标准窗口、租约、启动器和用户偏好恢复；读取失败同样保持隐藏。全过程不得出现第二个 Overlay、致命日志、无障碍点击或手势事件。
22. MediaSession 通道：在不清数据、不注入私有广播的前提下，依次让蓝牙、本机音乐、U 盘和爱趣听各播放一首带可信同步歌词的歌曲；每次切换都观察日志中的选中组件、WebView 的歌名 / `packageName`、歌词首行和进度连续更新。切换后不重启应用，打开设置并请求状态 / 点击“查找歌词”时字段必须已是新来源；暂停当前曲目后位置冻结，恢复后继续；停止或会话消失后旧歌词清除且低频刷新不回接旧暂停来源；首次只收到未知位置时保持静默，收到有效位置后再开始同步。若当前车机无法安全切换某通道，只记录该通道的客观阻断，不把 `dumpsys` 静态存在误记为播放通过。
