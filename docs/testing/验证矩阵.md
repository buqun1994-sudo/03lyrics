# 03lyrics 验证矩阵

## 1. 环境入口

1. 本机环境检查：`node scripts/check-local-environment.mjs`
2. 追加车机连接检查：`node scripts/check-local-environment.mjs --device`
3. 文档底座检查：`node scripts/check-project-docs.mjs`
4. Skill 结构检查：`node scripts/check-skills.mjs`
5. Git 文本检查：`git diff --check`
6. 自动覆盖安装与基础 smoke：`node scripts/install-and-smoke.mjs`

实际 JDK、Android SDK 和 ADB 路径从被忽略的 `.codex/local-context.properties` 读取，不写死在命令或提交文档中。

目标车机需要 instrumentation 时，不得运行会枚举全部在线设备并按测试应用流程重装目标包的 Gradle `connected*AndroidTest`。必须先构建 APK，再从本机上下文读取目标 serial，通过 `adb -s` 保留数据安装并定向执行 `am instrument`；完成后重新运行正式 debug 包覆盖安装与基础 smoke。只有允许清除状态的专用模拟器或一次性测试设备可直接使用 `connected*AndroidTest`。

## 2. Android 自动验证

| 变更类型 | 必须执行 |
|---|---|
| 只读查询 | 不默认跑构建 |
| 文档、规则、Skill、脚本 | 文档检查、Skill 检查、`git diff --check` |
| Kotlin 纯规则或缓存策略 | 直接相关单测；没有对应单测时执行受影响模块编译 |
| Android 配置、普通资源 | `assembleDebug` + 自动覆盖安装与基础 smoke |
| 标准浮窗尺寸或窗口动效 | `assembleDebug` + 自动覆盖安装 + 进入/系统返回录屏逐帧 smoke；复核静止边界为 `1230 x 810px` |
| Android 权限、安全、签名或数据迁移 | 相关单测、`lintDebug assembleDebug`，并按风险补验证 |
| 设置菜单或服务内重启 | `testDebugUnitTest assembleDebug` + 保留数据覆盖安装；实机核对“显示 / 系统”切换、全宽重启操作、唯一前台服务/Overlay/监听和致命日志 |
| 商业权益、设备身份、许可证或安全存储 | 商业领域与安全定向 JVM 测试、`testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest`、`assembleRelease` 隔离编译；定向安装测试 APK 后用 `adb -s <serial> shell am instrument -w -e class com.tcrrry.desktoplyrics.CommercialSecurityInstrumentationTest com.tcrrry.desktoplyrics.test/androidx.test.runner.AndroidJUnitRunner`，最后重新覆盖安装正式 Debug APK |
| 歌词匹配、外部源解析、请求协调或同源翻译 | `DirectLyricsRepositoryTest`、`DirectLyricsRepositoryOrchestrationTest`、`LyricsResolutionCoordinatorTest` + 全量 JVM 单测；翻译补时间戳缺行/容差检查，必要时受控网络 smoke |
| 车机状态、多值窗口占用、跨应用租约和顶栏几何 | `IcarDisplayStateMonitorTest`、`SurfaceOccupancyLeaseStateTest` + 自动覆盖安装 + 最简状态切换 smoke；完整组合由用户主测 |
| 缓存 | `LyricsCachePolicyTest`；涉及 SQLite 行为时补并运行 `LyricsCacheInstrumentationTest` |
| 悬浮层 HTML/CSS/JS | `assembleDebug` + 自动覆盖安装 + 最简截图/日志 smoke；完整交互由用户主测 |
| 启动、停止、开机恢复 | `SettingsBehaviorTest` + `assembleDebug` + 自动覆盖安装 + 最简启动 smoke；缺权启动至少观察 `10` 秒并检查恢复通知、前台服务异常和通知监听绑定，真正重启闭环由用户主测或另行授权 |

在当前本机配置下，需要完整验证时由以下逻辑步骤组成；普通敏捷施工不默认执行完整集：

```text
从 .codex/local-context.properties 读取 JDK17_HOME
以该 JDK 运行 ./gradlew testDebugUnitTest lintDebug assembleDebug
```

## 3. 单元测试覆盖

1. `DirectLyricsRepositoryTest`：歌词类型、同源翻译必须带同步时间轴、标题/歌手/专辑四级证据、显式准入与排序分分离、明确不同歌手硬拒绝、轻微拼写、双语标题桥接、跨文字歌手展示名完整片段、专辑末尾独立发行类型、同文字任意子串和无分隔发行词反例、跨文字体系未知态、证明重放与策略版本、同源重复、单侧版本省略为近似、明确版本冲突拒绝、版本证据排序、普通括号附注排序、合作歌手跨字段、时长边界、单来源、多发行候选和 LRCLIB 精确参数；`DirectLyricsRepositoryOrchestrationTest` 覆盖快来源不等待慢来源、两条不同来源正文通道、首轮耗尽立即兜底和总截止；`LyricsResolutionCoordinatorTest` 覆盖最新请求取消、瞬时失败只重试一次和完成无匹配不重试；`DirectLyricsRepositoryNetworkInstrumentationTest` 仅在显式网络开关下验证目标车机冷启动精确路径、本地化目录证据路径、歌手展示名与发行后缀目录路径、单侧现场版标记，以及同歌手近时长错误候选不能抢占正确结果。
2. `IcarDisplayStateMonitorTest`：启动器表面策略、`window_mode=0/1` 的无冲突区域、`2/3` 的标准浮窗占用、未知窗口模式保守回顶栏、外部占用租约覆盖系统清晰状态、有效几何保持可见、五类动态图标和顶栏几何；`SurfaceOccupancyLeaseStateTest` 覆盖租约初始回放、重复状态抑制、监听移除和晚订阅状态。
3. `LyricsCachePolicyTest`：缓存预算、清理目标、频率上限、淘汰偏好、时长 key 查找窗口和缺少翻译字段的旧载荷一次性刷新。
4. `LyricsCacheInstrumentationTest`：独立测试数据库中的版本 `3` 升级清理、读取前时长与完整证明复核、旧规则错误候选拒绝、双来源证明持久化和可选翻译字段持久化。
5. `SettingsBehaviorTest`：双授权有效进入唯一运行态；悬浮权限缺失或通知使用权缺失进入恢复态且不清除自动启动意图；`ACTION_STOP` 无论授权状态都进入用户主动停止并清除该意图。
6. `CloudDeviceCommercialGatewayTest` 使用同一 HTTP / JSON fixture 覆盖八个接口：首次联网试用、重复试用、公开活动、无活动、无效 / 过期 / 不可用码、staging / production / 零折金额边界、微信 / 支付宝金额一致、报价过期、`quote_changed` 二次确认、支付成功、`already_owned`、device token 响应丢失后的恢复、同指纹有旧钥 / 无旧钥恢复、不同指纹拒绝和有效许可证离线保留。
7. `CommercialStateMachineTest` 覆盖试用 / 过期 / PRO / 查询错误、PRO 刷新不闪回广告、金额展示值透传、输入不篡改旧报价、改价确认、权益 / 订单 / 二维码互斥页面、短暂轮询失败保留二维码、支付成功 / 订单过期及恢复状态；`CommercialSecurityTest` 覆盖原始 challenge、四行 poll 原文、先验签后解析、产品 / 公钥 / keyId / 密钥版本 / 时间边界和离线宽限；`CommercialAccessTest` 覆盖存储失败、可信时间回退与有效 PRO 准入；`CommercialVariantIsolationTest` 和 `CommercialLayoutContractTest` 覆盖 fixture 金额与 Release 源集隔离、PRO 完整 `GONE`、主题色入口和三页物理结构。
8. `CommercialSecurityInstrumentationTest` 使用独立测试 AES 别名验证设备 KeyStore 原始 challenge 签名、SPKI 导出、密文位于 `noBackupFilesDir` 且不含明文，以及 Debug fixture 通过正式协议主链生成可验签试用许可证；测试后删除独立测试记录和测试 AES 别名，不删除正式设备身份键或应用数据。

## 4. 目标车机运行级 smoke

AI 在每次实现完成后先自动执行保留数据覆盖安装与本次改动的最简 smoke，通过后交给用户执行完整场景。完整 smoke 包含：

1. 授权前置：受控部署已提供通知使用权和悬浮窗权限，前台服务能正常启用；应用设置页不承担授权入口。
2. 播放闭环：播放时歌词与时间线同步；同一首可信歌词暂停后冻结并保持显示，恢复播放后从冻结位置继续；暂停时首次出现的新曲目不提前显示，切歌、停止和无会话会清除旧歌词。默认开启翻译时，同源翻译歌曲在桌面作为原文附属小字显示，顶栏一行显示当前原文与翻译、两行再保留下一句原文；无翻译歌曲只显示原文，关闭开关立即恢复原布局。
3. 表面切换：壁纸、地图、车辆设置、行车记录仪、应用中心和本项目设置页打开/关闭时表面与可见性正确；任一标准浮窗打开时桌面歌词退回顶栏，顶栏歌词不消失。
4. 动态图标：无线充电、存储和守护模式等已知图标变化后，歌词左边界实时更新且不重叠。
5. 生命周期：主动停止不恢复；保持启用时应用升级和车机重启后恢复。
6. 安全界面：倒车影像和车辆警告出现时，歌词层不覆盖其高优先级界面。
7. 主题切换：歌词服务运行且歌曲正在播放时切换深色/浅色，设置页和当前歌词表面同步换色，歌词行、播放进度和悬浮表面保持连续；该深浅主题闭环已经用户主测通过。粉色主题必须读取公开键 `33`，在导航、分段、开关、折扣标签和商业动作上保持一致；其它主题键不得以纯规则单测代替实机通过结论。
8. 标准浮窗：打开时整个窗口从底部向上进入，系统返回或任务退后台时整个窗口向下退出；底层页面静止，结束后窗口仍为 `1230 x 810px`，无尺寸跳变、残影或背景分层错位。
9. 窗口占用信号：桌面读取值为 `0`，左侧 ADAS / 充电卡片单独展开为 `1`，两者均允许桌面歌词；上述标准浮窗前台为 `2`，左侧卡片与标准浮窗同时存在为 `3`，两者均退回顶栏。其它值或读取失败时歌词保守留在顶栏；关闭冲突窗口后按当前启动器状态恢复。
10. 系统菜单：左栏“显示设置 / 系统设置 / 权益中心”使用固定图标列与四字标签对齐，切换不启动新 Activity；“系统设置”页只存在一个占满右侧可用宽度的“重启悬浮歌词”操作，不显示授权开关，也不打开系统授权页面。缺少任一授权时点击只提示授权未完成，不启动或破坏现有服务。
11. 手动重启：点击后同一 `LyricsOverlayService` 实例完成资源重建，`PREF_AUTO_START` 与显示偏好不变；仅存在一个前台服务、一个 `APPLICATION_OVERLAY` 窗口和一套 MediaSession/音频/AVRCP/车机监听，播放状态继续更新且无致命日志。
12. 表面占用租约：覆盖安装后，`cmd package query-services --brief -a com.tcrrry.icar.surface.action.ACQUIRE_OCCUPANCY_LEASE` 必须发现本应用的 `SurfaceOccupancyLeaseService`；`03桌面` 右侧面板开始展开即退回顶栏，展开和收起动画全程保持顶栏，完全收回后重新按第 9 条窗口值与用户偏好计算。
13. 授权恢复退化：保留 `PREF_AUTO_START=true`，临时撤销悬浮权限后从停止状态请求启动，至少观察 `10` 秒；必须记录启动来源、两项授权和 `outcome=recovery`，不存在 `RemoteServiceException`，`LyricsOverlayService` 结束且 `MediaListenerService` 保持系统绑定，并存在点击后进入现有设置页的恢复通知。恢复原授权并显式启动设置页后，必须记录 `outcome=running`、清除恢复通知，只存在一套服务、Overlay 和监听。测试结束恢复临时授权状态，不自动重启车机。
14. 商业综合卡与主题：试用态只在“显示设置 / 系统设置”顶部显示中性大底框并避开系统拖动横条；左侧状态垂直居中，右侧把“现在购买 PRO”、立享折扣和价格对比作为一个整体，上行标题紧邻折扣，下行价格右缘与折扣右缘均为屏幕 `x = 1775px`，末端保留大箭头。折扣标签、箭头、主按钮和支付方式选中态与导航使用同一强调色。点击整卡进入权益主页后，卡片及其高度占位立即消失；PRO 后同样保持消失，左栏保留金黄 PRO 角标。综合卡隐藏时显示页首个分段必须为 `y = 207..279px`、系统操作卡为 `y = 146..272px`；恢复试用并重新显示综合卡后，显示页首个分段必须恢复为 `y = 338..410px`。
15. 商业页面流：权益主页不出现 slogan，顶部居中显示试用权益状态和剩余时间；顶部状态组必须为 `[1040,146]..[1814,234]`，底部购买组必须为 `[1040,723]..[1814,844]`，两者距对应页面边缘均为 `56px`。中间营销组必须为 `[1247,393]..[1606,565]`，上行购买标题紧邻右侧折扣，下行双列原价 / 限时价与上行同宽且限时价右缘和折扣右缘一致；营销组在上下两组之间垂直居中，不显示方向箭头。PRO 完成组必须为 `[1040,408]..[1814,582]`，包含金色皇冠、居中主标题和永久权益说明，营销、支付与恢复入口全部隐藏。点击后主页消失并显示订单详情，点击支付后订单详情消失并显示固定二维码。轮询网络失败仍留在二维码页；Debug 标记成功后二维码消失、自动回到同一居中完成组并显示“支付成功 / 权益生效中 · 永久”。
16. 报价与订单：Debug 默认自动读取 fixture 当前活动并显示 `¥0.02 / 5折 / ¥0.01`，`minimumChargeApplied=false`；订单说明左对齐、结果右对齐，折扣码控件比例稳定，最终价格独立成行。正常态订单返回入口从 `y = 146px` 开始，“支付”必须为 `[1295,781]..[1559,844]`，上下外缘距页面均为 `56px`；微信 / 支付宝选择条随支付组共同定位于 `y = 689..740px`，不要求与权益页“前往支付”同位。任意无效码应用后显示“折扣码无效 / 无折扣 / ¥0.02”，仍可按原价创建微信或支付宝订单。`commercial_debug_payment=changed` 时展示最新原价报价并等待再次确认；`expired` 回订单页；`owned` 不生成重复订单。
17. 商业恢复：`commercial_debug_recovery=same` 使用 recover challenge 完成换钥并进入 PRO；`different` 明确显示设备不一致；`network` 保留原本地权益，不显示成未购买。未完成支付关闭并重开设置页后恢复二维码与自动轮询。
18. 商业门禁：Debug 试用时设置页启动后歌词服务、唯一 Overlay、MediaSession 和歌词请求资源正常；切到过期或无本地许可证的查询失败后，歌词仓库、协调器、缓存、协程、MediaSession、WebView、Overlay 和监听均释放，`PREF_AUTO_START` 保持为真；切回有效试用后只恢复一套资源。
19. Release 隔离：Release APK 只构建不安装，解包后不得命中 `0.02 / 0.01 / 49.00 / 29.40 / icar 03 / debug-fixture / fixture.03lyrics.invalid / commercial_debug_ / DEBUG FIXTURE`。默认 Debug BuildConfig 必须为 `fixture`，本轮不得使用 staging / production 构建参数运行应用。

## 5. 交付记录

1. 必须逐项写明实际执行命令、覆盖闭环和结果。
2. 未执行实机项必须说明客观阻断，如未授权安装、设备离线或车辆场景不可用。
3. 剩余人工确认必须压缩为具体动作，不能要求用户“整体回归”。
4. 自动安装或最简 smoke 未通过时不得进入用户主测阶段；修复后必须重新构建、安装并 smoke。
5. 用户主测有问题则继续迭代；用户确认无问题后仍需等待明确提交指令，不把测试反馈自动解释为 Git 授权。
