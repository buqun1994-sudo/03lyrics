# 本地开发环境

## 1. 逻辑依赖

1. JDK 17。
2. Android SDK，至少包含 Android 34 Platform、Build Tools 34.0.0、Platform Tools 和 Command-line Tools。
3. 仓库内 Gradle Wrapper。
4. Node.js，用于仓库文档、Skill 和环境快检脚本。

## 2. 本机配置入口

1. 将 `.codex/local-context.properties.example` 复制为 `.codex/local-context.properties`。
2. 本机文件至少配置 `JDK17_HOME`、`ANDROID_SDK_ROOT` 和 `PRIMARY_ADB`。
3. 需要构建 staging 时，通过 `DEVICE_COMMERCE_STAGING_PUBLIC_CONFIG_FILE` 和 `DEVICE_COMMERCE_STAGING_SIGNING_PROPERTIES_FILE` 记录仓库外公开信任配置与签名 properties 的本机路径；这里只保存文件指针，不保存口令、私钥或 keystore 内容。
4. 需要日常车机安装和 smoke 时配置 `VEHICLE_ADB_SERIAL`；商业 instrumentation 不读取该值，只有独立测试设备才另行配置 `COMMERCIAL_TEST_ADB_SERIAL` 和 `COMMERCIAL_TEST_DEVICE_ROLE=dedicated-test-device`。备用 ADB、共享工具链说明和 `NewProject` 模板源均为可选项。
5. `local.properties` 只配置 Android SDK，永不提交；可提交示例不得包含个人路径。

## 3. 检查入口

1. `node scripts/check-local-environment.mjs` 检查 JDK、SDK、Build Tools、Platform Tools 和 Gradle Wrapper。
2. `node scripts/check-local-environment.mjs --device` 额外检查当前 ADB 设备列表中是否存在目标车机。
3. `node scripts/install-and-smoke.mjs` 以 ADB 非流式传输将当前 debug APK 保留数据覆盖安装到目标车机，先启动设置页解除包的 stopped 状态，再幂等追加并验证“歌词窗口避让”无障碍组件且保留已有服务列表，随后检查版本、进程和致命日志。服务绑定只认可目标组件自己的 `ServiceRecord`，不得借用其它服务或 WebView 记录中的绑定字段；目标车机已复现流式安装无输出卡住，脚本不再依赖该模式。
4. `node scripts/run-commercial-security-instrumentation.mjs` 不是普通收尾入口。它只读取 `COMMERCIAL_TEST_ADB_SERIAL`，并要求角色为 `dedicated-test-device`；缺少独立配置、误指向 `VEHICLE_ADB_SERIAL` 或角色不匹配时，会在任何 ADB 操作前退出。允许执行后，脚本核对正式包、测试包和测试设备已安装包的签名，完成隔离测试、专用清场、辅助包卸载、正式权益记录哈希比对和同一测试设备的恢复 smoke。用户日常车机只有在当次明确授权、角色为 `persistent-user-vehicle` 且显式传入 `--user-approved-persistent-vehicle` 时才可例外；不得由历史授权、商业改动或收尾 Skill 自动传入该参数。
5. 首选 ADB 不可用时，先停止继续操作并核对设备状态，再决定是否使用 `FALLBACK_ADB`；禁止同时运行相互冲突的 ADB Server。

## 4. 边界

1. JDK、Android SDK、ADB 二进制和 Gradle 缓存属于本机共享工具链，不复制进仓库。
2. ADB 只用于开发、安装、日志和实机验证，不进入正式运行主链。
3. 构建脚本不得读取提交文档中的个人绝对路径；统一由当前会话从本机上下文注入 JDK 环境。
4. 普通施工后的 debug APK 保留数据覆盖安装和应用范围最简日志检查属于默认收尾动作；清除数据、卸载、重启设备、安装 release 或抓取可能包含个人信息的广泛日志仍需用户当次明确指令。
5. 商业 instrumentation、androidTest APK 安装、为测试暂停无障碍和强制结束正式应用均不属于默认车机验证。一次性模拟器可清状态；独立物理测试设备必须使用单独 serial。用户车机上的例外必须取得当次明确授权，且不得自动重启设备。

## 5. Device Commerce 构建环境

1. 默认 Debug 的 `deviceCommerceEnvironment=fixture`，完全在应用进程内模拟九个协议接口，不读取远端 API 基址，也不得用该结果宣称 staging 或真实支付通过。
2. 测试环境恢复后，只有显式使用 `-PdeviceCommerceEnvironment=staging`，并同时提供 `deviceCommerceStagingApiBaseUrl`、`deviceCommerceStagingLicenseKeyId`、`deviceCommerceStagingLicensePublicKeyBase64`、`deviceCommerceStagingSigningCertSha256` 和 `deviceCommerceStagingSigningPropertiesFile` 时，Debug 才装配 staging。本机会话先从 `DEVICE_COMMERCE_STAGING_PUBLIC_CONFIG_FILE` 指向的公开信任包读取基址、公钥和 `keyId`，再从 `DEVICE_COMMERCE_STAGING_SIGNING_PROPERTIES_FILE` 指向的配置定位仓库外 keystore，并以其证书计算 signer 摘要；这些本机路径不得写入构建脚本或提交文档。基址、公钥、`keyId` 和 signer 摘要只允许从构建入口进入集中装配，不得从 Activity、领域层或普通资源覆盖。
3. Release 固定选择 production，但 `deviceCommerceProductionApiBaseUrl`、`deviceCommerceProductionLicenseKeyId`、`deviceCommerceProductionLicensePublicKeyBase64`、`deviceCommerceProductionSigningCertSha256` 缺任一项即 fail closed；只要提供其中任一项，构建阶段就要求整组配置完整且 production 基址为 HTTPS。仓库不提供 production 默认域名，不提交真实构建参数，也不因执行 `assembleRelease` 访问网络。正式签名属性可通过 `-PdeviceCommerceProductionSigningPropertiesFile=<repository-external-signing.properties>` 注入。
4. 许可证公钥为 P-256 SPKI DER Base64，可随客户端公开；许可证私钥、支付密钥、pepper、token 和服务端环境变量不得进入客户端构建参数。
5. staging APK 必须使用长期稳定且独立于自动 Debug 证书的签名身份；production 将来使用另一套独立身份。签名配置缺失时 staging 构建必须失败，不允许静默回落到开发机 Debug 证书。
6. Release 固定执行 R8 优化、混淆与资源收缩并显式关闭调试；`app/build/outputs/mapping/release/mapping.txt` 只用于内部崩溃还原，不上传到公开 Release。普通 Debug 不启用 R8；正式发布前必须先用相同 Release 规则完成构建和 smoke，禁止对已签名 APK 再做二次加壳或后处理。

## 6. 用户协议二维码构建配置

1. Debug 默认使用 `userAgreementEnvironment=staging`，可显式传入 `-PuserAgreementEnvironment=staging|production` 选择二维码地址；Release 固定使用 production，不接受外部参数覆盖。
2. 构建把环境和对应的 HTTPS 地址注入 `BuildConfig.USER_AGREEMENT_ENVIRONMENT` / `BuildConfig.USER_AGREEMENT_URL`，设置页只在本地用二维码编码器生成图像，不请求协议服务、不依赖运行时下发，也不使用版本号判断环境。
3. 当前固定地址为测试 `https://staging.9studio.fun/icar03/terms`、正式 `https://9.9studio.fun/icar03/terms`。将来页面迁移优先在服务端对固定地址做跳转，避免客户端跟随页面变更重新发版。
