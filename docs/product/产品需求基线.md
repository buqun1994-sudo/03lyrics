# 03lyrics 产品需求基线

## 1. 产品定位

1. 产品名称与 Android 界面名称均为“03歌词”。
2. 目标用户：在 iCAR 03 原厂桌面、地图和其他车机应用中需要同步歌词的车主。
3. 核心问题：原厂界面没有稳定、克制且能适应顶栏动态图标的同步歌词显示。
4. 成功结果：播放歌曲时显示匹配正确、进度同步且不遮挡原厂关键区域的歌词；停止、切换界面和重启后状态符合用户意图。

## 2. 核心用户路径

1. 目标车机通过受控部署流程完成通知使用权、悬浮窗和“歌词窗口避让”无障碍授权后打开应用；普通 APK 不能自行取得这些特殊访问。前两项是歌词服务启动门槛；无障碍未启用或暂时失联时不扩大壁纸歌词区域，而是保守使用顶栏歌词。
2. 用户开启歌词服务并播放音乐。
3. 应用读取公开 MediaSession 数据，命中缓存或向公共歌词源查找同步歌词；蓝牙、本机音乐、U 盘、爱趣听以及其它公开 `USAGE_MEDIA` 音乐会话都走同一条播放主链，不按播放器包名限制能力。
4. 地图、任意标准浮窗、已取得的桌面区域占用租约或未知 Dock 状态显示顶栏歌词；原厂壁纸状态仅在桌面歌词区域未被占用且用户允许时显示桌面歌词。左侧 ADAS / 充电卡片和左侧、中央 Dock 不占用该区域；最右侧 Dock 展开时只裁剪壁纸歌词下边界，收起后恢复。空调页展开、过渡或状态未知，以及已取得的全屏独占租约均隐藏全部歌词；释放后立即按最新原车窗口状态和用户偏好统一重算，不回放进入前的表面，也不闪出临时顶栏。
5. 用户可在同一设置窗口切换“歌词设置 / 服务状态 / 歌词缓存 / 歌词查找 / 权益中心 / 关于”：分别调整顶栏与壁纸歌词、查看和清理缓存、按当前歌曲人工选择歌词、查看用户协议二维码，并在歌词层异常时手动重启运行链路。
6. “歌词查找”自动填入当前歌曲名、歌手和专辑；用户可在单行工具条中修正字段后搜索，查看来源、歌曲、歌手、专辑和时长，点选结果后立即替换当前歌词。人工选择只绑定搜索开始时的当前播放身份，切歌或缺少有效当前歌曲时不得误绑。
7. 两项授权均有效时，进入或返回设置页可恢复当前歌词服务；“开机自启动”默认开启，并独立决定车机重启或应用升级后是否恢复。用户主动停止服务时同时清除自动恢复意图。
8. 自动恢复时若任一授权失效，应用不崩溃、不后台弹页，也不把“保持启用”改成主动关闭；歌词运行资源正常结束，并保留可点击进入现有设置页的恢复通知。授权重新有效后，下一次合法启动清除恢复状态并只恢复一套歌词运行资源。

## 3. 当前 V1 范围

1. MediaSession 歌曲信息、播放状态与进度同步；蓝牙 `com.android.bluetooth/A2dpMediaBrowserService`、本机音乐 `com.tencent.wecarflow/com.mengbo.service.play.customplayer.HddPlayerService`、U 盘 `com.tencent.wecarflow/com.mengbo.service.play.customplayer.UsbPlayerService`、爱趣听公开会话 `com.tencent.wecarflow/.player.MediaPlaybackService` 及其它合格公开媒体会话均支持；同一曲目已显示可信同步歌词后暂停时冻结当前行并保持显示，暂停时首次出现的新曲目仍等待真正播放。
2. LRCLIB、QQ 音乐、网易云多源同步歌词匹配；当前选中的 QQ 或网易云结果自身提供逐句翻译时，按用户设置随原文显示，不跨来源拼接或机器翻译。
3. 车机顶栏和桌面两种歌词表面及动态顶栏安全几何。
4. 本地歌词自动缓存、当前歌曲人工覆盖、缓存概览与清理、开机恢复和完整显示设置。
5. 无可信歌词时保持静默，不用低质量结果填充界面。
6. 设置页、顶栏歌词和桌面歌词跟随车机系统深浅主题，主题切换不打断当前歌词进度；车机系统主题色跟随当前未适配成功，不纳入已验收能力。
7. 原车设置、行车记录仪、账号、应用中心或同规格第三方页面打开时，桌面歌词自动退回顶栏且顶栏歌词持续可见；左侧 ADAS / 充电卡片与左侧、中央 Dock 展开时桌面歌词保持不动；最右侧 Dock 展开时壁纸歌词窗口下边界保持在 Dock 真实上沿之上，且下边缘渐隐随新的可见底边结束，收起后恢复；空调页占用和全屏独占租约期间顶栏与壁纸歌词均隐藏，释放后不闪出临时顶栏。会覆盖桌面歌词区域的自定义桌面面板仍通过通用占用租约退回顶栏，释放后按当前桌面状态恢复。
8. “歌词设置”固定分为“顶栏歌词 / 壁纸歌词 / 通用”：顶栏支持一行 / 两行及独立小 / 标准 / 大字号；壁纸支持启用、独立字号、歌词模糊、歌词阴影、密集 / 标准 / 宽松排版和顶部 / 中间焦点；通用支持开机自启动与逐句翻译。壁纸歌词阴影、开机自启动和逐句翻译均默认开启；壁纸歌词设置仅在壁纸模式生效。
9. “服务状态”提供当前悬浮歌词服务总开关和“重启悬浮歌词”，不展示通知使用权或悬浮窗授权状态，也不打开目标固件上无法完成触摸操作的系统授权页面。授权不足时使用设置窗口内的普通信息弹窗说明结果，不使用平台 Toast 或系统对话框。“重启悬浮歌词”是一次性恢复动作，不保存为布尔设置；两项系统授权有效时执行，完成后保留显示偏好与自动恢复意图，并只留下一个前台服务、一个歌词悬浮窗和一套播放监听。
10. 开机或升级恢复缺少授权时显示常驻恢复通知，通知只打开现有 `MainActivity`，不后台弹页、不直接打开系统授权页，也不自行授权。
11. 顶栏可以在前奏阶段预览第一句同步歌词，但长句横向滚动只能从该句时间点开始；回退到该句时间点之前时，文字必须回到起始位置并保持静止。连续长句切换时，上一句保持末尾位置退出，下一句必须直接从起始位置进入，不得出现可见的反向回滚。
12. 顶栏与桌面歌词切换采用克制的表面交接：旧表面先淡出，完全不可见时再切换位置和布局，新表面随后淡入；切换过程中不得同时出现两套歌词、可见跳位、闪帧或残影，连续触发时只落到最后一个目标表面。
13. 壁纸歌词在当前真实可视区域上下边缘轻微渐隐到透明，避免文字被窗口边界直接截断；最右侧 Dock 裁剪后，底部渐隐必须结束于裁剪后的边界。渐隐不得染色壁纸、削弱中部当前歌词、影响顶栏显示，或引入持续刷新和明显性能回退。
14. “歌词缓存”显示自动与人工缓存合计占用、`128 MiB` 上限、歌曲数量、按当前平均条目大小估算的剩余可缓存歌曲数，以及当前歌曲的来源、候选版本、自动 / 手动、翻译及更新时间；只支持删除当前歌曲缓存，当前为人工选择时另提供“恢复自动匹配”。容量达到上限后由缓存策略自动淘汰旧项，不提供全量清空入口。
15. 人工搜索每来源最多展示 `8` 条、总计最多 `24` 条，只按元数据和时长排序，不套用自动匹配的准入淘汰；用户点选后才下载该候选正文，且只有同步时间轴歌词可以写入人工覆盖。读取优先级固定为“人工选择 > 自动缓存 > 在线自动匹配”，恢复自动匹配只删除人工覆盖并立即重新解析当前歌曲。
16. 所有合格媒体通道共享同一套选源与时间线规则：公开媒体语义和系统会话顺序决定当前来源，播放中优先于缓冲，暂停来源保持粘性；停止历史会话、语音 / 提示音和没有有效媒体语义的会话不接管歌词。播放器回报的零值 / 未来时间戳或未知位置不得造成进度跳变，首次没有可信位置时保持静默。

## 3.1 发行边界

1. 面向普通用户分发的 APK 不具备零点击开启通知使用权、悬浮窗权限或无障碍服务的能力；把同一 APK 发给另一台车机不会携带开发机或其他设备上的授权状态。当前目标车机的外部受控调试授权只属于部署流程，不是应用运行时的 ADB 依赖。
2. 若产品要求“安装后无需用户操作即可可用”，发行物必须由车厂作为平台签名或特权系统组件预装，并在系统配置中授予悬浮窗 AppOp、通知监听访问权和窗口避让无障碍服务；这不是普通 APK 安装流程可以替代的能力。

## 3.2 商业权益与设备购买

1. 设置页左栏标题“03歌词”在标题区居中，试用 / 过期 / Pro 使用标题右下角的小状态角标；“歌词设置 / 服务状态 / 歌词缓存 / 歌词查找 / 权益中心 / 关于”六类入口采用固定图标列与左对齐标签，仍在同一 Activity 内切换。“关于”固定在左栏底部，协议卡只显示“用户协议”和离线生成的二维码。
2. 未购买 PRO 时，四个非权益分类顶部显示与普通设置卡同底色的大型综合卡：左侧垂直居中显示试用剩余时间或异常状态，右侧把购买标题、动态折扣和价格对比收成一个整体；购买标题紧邻折扣角标，价格行与折扣角标右对齐，并保留明显箭头。整卡只进入权益主页，不直接创建订单；进入“权益中心”或 PRO 稳定生效后，综合卡及其布局占位完全消失。综合卡消失后，非权益内容仍保留标准页面顶部留白，不贴近系统拖动横条。
3. 权益页、订单详情页和二维码支付页是互斥内容状态，不在同一滚动页面上下堆叠。未购买且存在可购买报价时，权益页顶部居中显示试用权益状态和剩余时间；中间板块把大号“现在购买 Pro”、其右侧动态折扣以及下方双列原价 / 限时价作为一个整体水平居中，并在顶部状态组与底部购买组之间垂直居中，视觉上略高于整页中心；价格组与折扣角标共用右边界。无报价、确认中、无法确认或其它只有状态与底部动作的状态下，状态和恢复反馈必须位于页面顶部留白与底部动作组之间的可用区域中心，不按整页高度机械居中，并与底部操作保持明确间距；底部只保留动作入口。不显示 slogan、方向箭头，也不复刻订单明细表。顶部状态组与底部“前往支付 / 恢复购买”组使用相同页面边距。PRO 生效后改为金色皇冠、居中大号“Pro 权益已生效”和“权益生效中 · 永久”的独立完成态，不继续沿用未购买状态的顶部信息布局。
4. “前往支付”切换到订单详情；商品、原价、折扣码、折扣和最终价格使用左说明 / 右结果对齐，最终价格独立成行，紧凑折扣码输入与应用动作保持同一比例。订单明细组与支付组分别使用相同的页面顶部、底部边距；不再要求订单“支付”与权益“前往支付”处于同一屏幕位置，微信 / 支付宝选择条随订单支付组整体定位。无效、过期或不可用折扣码显示对应结果与云端原价报价，允许用户确认一次后直接下单。
5. 用户确认当前报价后才创建订单。`quote_changed` 必须显示 `latestQuote` 并等待再次确认；`already_owned` 直接进入 PRO，不生成二维码或重复订单。
6. 创建订单后切换到固定二维码页，显示 API 返回的二维码、最终金额、订单有效期和付款状态；按服务端建议间隔自动轮询。短暂网络失败保留二维码和订单，不显示“未购买”；支付成功后自动返回权益页并显示 PRO 永久生效。
7. Android UI 不计算订单金额。默认本地 fixture 使用 staging 边界 `¥0.02 / 5折 / ¥0.01`；production `¥49.00 / 6折 / ¥29.40` 与零折最低 `1 分`只存在于 Debug fixture 或自动化断言，不进入主资源或 Release。
8. 首次试用必须联网取得签名试用许可证；固定七天的云端 `trialEndsAt` 不得因重复启动、进程重建、重装或同指纹换钥而重置。每张试用许可证的 `expiresAt` 与 `offlineGraceUntil` 最长 `24h`，短租约到期且七天权益仍有效时，使用当前设备密钥重新走试用签发流程；永久 PRO 许可证必须声明 `validity=permanent`，`expiresAt`、`offlineGraceUntil`、`trialEndsAt` 均为 `null`，不安排续签定时器。车辆启动、新的歌词服务生命周期、用户点击重启服务和打开新的设置页都先验签本地许可证，同时异步通过唯一 `license/check` 查询云端状态。`active` 不签发新许可证、不生成新的 `licenseId`、不改写本地许可证字节或时间；`revoked` 清除本地凭证并释放运行资源；网络失败保留仍有效凭证并记录待复核，在下一生命周期重试，不用高频轮询或 `24h` 自动重试冷却。
9. 恢复购买只覆盖同设备：新公钥使用 recover challenge，旧私钥存在时附加旧钥签名，旧钥丢失时允许同指纹恢复；不同指纹必须拒绝。启动查询收到明确的 `device_key_mismatch` 时自动尝试恢复一次，成功后直接进入原权益；网络、撤权、验签、存储、时钟和指纹不匹配不得触发自动恢复，手动“恢复购买”继续作为失败后的入口。不引入账号、邮箱、`recoveryCredential` 或跨设备迁移入口，恢复出厂后指纹变化不承诺恢复。
10. Debug 默认只连接进程内 fixture；测试环境恢复且显式提供 staging 许可证公钥、`keyId`、长期 APK 签名和对应证书 SHA-256 后，测试包才使用 `https://api-staging.9studio.fun`。Release 使用 R8 优化、混淆和资源收缩，只接受 production 基址、公钥、`keyId`、正式签名与对应证书 SHA-256；任一商业配置缺失、格式错误或运行包 signer 不匹配均 fail closed。本轮不访问 staging / production，也不据本地模拟宣称真实支付通过。
11. 云端 `license/check` 返回 `revoked` 后，客户端必须先让本地许可证和 device token 失效，不能继续离线放行，并释放歌词运行资源。`active` 只确认云端权益，不签发或替换许可证；试用短租约到期时才重新取得下一张最长 `24h` 的试用许可证，固定七天截止时间不重置。`not_started` 时不得静默沿用本地权益：没有本地许可证时进入试用开始，本地仍有试用时也使用原始首次打开时钟重新建立云端试用；本地 PRO 凭证则收敛为撤销。`device_key_mismatch` 才自动尝试一次同指纹恢复；网络失败保留仍有效凭证并记录待复核。购买 / 恢复成功签发的永久 PRO 只允许完整验签和持久化后开放门禁。

## 4. 明确不做

1. 不建设歌词服务器、账号系统、应用商店或在线推荐。
2. 不提供 `03桌面` 的应用列表、拖拽排序、APK 安装、卸载或快捷控制。
3. 不控制空调、车窗、车锁、座椅、驾驶辅助或其他车辆安全功能。
4. 不要求 root，不常驻 ADB，不依赖手机或电脑。
5. 不读取麦克风、录制系统音频或读取普通通知正文。
6. 不同时创建顶栏和壁纸两套歌词表面；始终复用唯一 WebView、唯一 Overlay 和既有互斥表面切换。

## 5. 验收口径

1. 同一歌曲在可信同步歌词已存在时，蓝牙、本机、U 盘、爱趣听及其它合格公开媒体会话均能在顶栏和桌面表面按播放进度显示正确行；切换通道后旧来源不会延迟覆盖新来源。
2. 地图、任意标准浮窗、已取得的桌面区域占用租约和未知 Dock 状态不会进入桌面大区域；已取得的全屏独占租约时，顶栏与桌面歌词均不可见；左侧 ADAS / 充电卡片和左侧、中央 Dock 单独展开不触发回退；壁纸状态仅在桌面歌词区域未被占用且用户开启对应设置时进入桌面表面。
3. 五个已知动态图标全部出现时，顶栏仍保留至少 `180 px` 可用宽度；未知图标状态不触发猜测位移。
